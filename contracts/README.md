# Design contracts

这个目录保存投放 Agent 的公开设计契约：业务语义如何跨连接器保持一致，怎样保留执行证据，以及素材恢复、初始化和分析需要哪些边界。它们供开发、评审和编写测试使用。

**全部文件都是 `artifact_type: "design_only"`、`runtime_loaded: false`、`enabled: false`。** JSON 可被解析不代表运行时已经加载这些规则；这些文件不是 JSON Schema，也不提供可执行接口、平台能力保证或真实投放授权。目录中的验收场景尚未作为运行时测试执行。

| 文件 | 设计范围 |
| --- | --- |
| [connector-contract.json](connector-contract.json) | 业务、平台适配、连接器和执行证据的分层；能力快照、对象身份、金额、分页、错误、范围授权与连接器切换。 |
| [creative-recovery.json](creative-recovery.json) | Meta 素材技术排障、疑似误拒的有限恢复、实质问题修正及证据不足分支；不同对象层级的影响和停止条件。 |
| [acceptance-scenarios.json](acceptance-scenarios.json) | 23 个未来实现的验收场景，涵盖未知写结果、能力范围、数值口径、恢复、上下文变化与批次授权。 |
| [experience-catalog.json](experience-catalog.json) | 32 条按工作流阶段组织的通用经验，区分工程要求、版本化能力、业务选择和诊断假设。 |
| [onboarding-extensions.json](onboarding-extensions.json) | 业务事实与来源、连接读写验证、条件问题、工作流 readiness、方法选择和上下文指纹的设计。 |

`format_version` 只标识这些设计数据的格式；它不是平台 API 版本，也不声明存在自动迁移器或校验器。对象中名为 `fields`、`required_scope` 或 `verification_needed` 的列表描述待实现的要求，不会自行执行校验。

## 设计约束

- **连接器可以替换。** API 与 MCP 都是传输和工具适配方式；本目录不依赖指定供应商，不附带 URL 端点或凭据。绑定例子的工具名和包装字段是虚构的，不能复制后直接调用。
- **能力必须有范围和证据。** 官方文档或 SDK 中出现字段，不代表当前账户、广告产品或连接器可以执行该动作。发现账户、读取成功、写入能力和业务授权分开记录；模拟证据不能证明线上可写。
- **身份和状态不能混淆。** 本地文件指纹、平台素材引用、creative、ad、帖子以及展示身份分别追踪；请求状态、配置状态、有效状态、审核、媒体处理和实际投放也分别记录。
- **数值保留口径。** 金额必须带币种、周期和逐字段单位契约；归因与时间粒度以实际生效及返回信息为依据；分页不完整、权限缺口、未知、真实零和无定义比率不能互相替代。
- **授权按整批范围继承。** 冻结计划关联上下文、账户、动作、预算、币种和时限；已覆盖动作可自动继续，实质变化则重新评估。创建非暂停广告本身可能产生花费，不能只在后续启用时检查授权。
- **不确定写结果先核对。** 切换连接器或恢复执行不能清除原 operation ID、已发生动作或案例尝试数。没有证据证明未创建前，不能把超时当成安全重试的理由。

这些原则没有指定固定的获客模型、收入模式、出价结构或测试阈值。`method_template` 默认未选择，只有当前项目明确选择的方法及参数才能进入计划。业务信息不完整时，允许开展不依赖这些缺口的资料整理、素材选择和离线准备；需要价值判断或发布时再检查相应依赖。

## 素材恢复的适用边界

[素材恢复说明](../docs/meta-creative-recovery.md)与 `creative-recovery.json` 共同区分四种情况：有证据的处理或引用错误、疑似误拒、已确认的实质问题、证据不足。

正常规格修复、重新上传、创建 creative、修改受支持的绑定、创建替代 ad 和请求复核是不同操作。技术故障和疑似误拒可以产生有限恢复候选，不应因为包含重传就一律排除。具体方法仍须具备当前能力、适用证据、允许范围、尝试次数、时间与花费边界。已确认内容或目的地存在实质问题时，必须处理该问题，不能将只改字节或身份描述为合规修复。

平台可能复用上传的素材引用；恢复成功也不证明文件指纹导致原拒登。审核通过、实际投放、学习状态、互动归属和业务效果分别验证，不承诺其中任何一项会随着新引用自动恢复。

## 如何用于实现

1. 选择当前功能实际需要的设计条目，并明确平台、广告产品、账户、操作和版本范围。
2. 将适用条目转为有类型校验、缺失语义、状态机与授权检查的实现；为未知配置返回明确缺口或 `unsupported`，不要静默忽略。
3. 将对应验收场景转为独立的离线测试或已授权的集成验证，记录实现版本与结果。仅能据此报告被验证的范围。
4. 真实动作需要独立核验连接能力、当前业务授权与对象状态。保留提交回执、原生对象读回、差异和不确定结果的核对记录。

文件内的 hash/fingerprint 用于绑定内容和检测变化，不证明来源真实性，也不等于数字签名。正式系统仍须实现自己的授权来源验证、存储保护和执行检查。
