# 一轮真实的投放快循环，跑完是什么样

这个文件夹只做一件事：让你在**不接账户、不装环境**的前提下，几分钟内看清这套东西在真实投放循环里
到底替你做了什么判断、又拒绝了哪些判断。

**先看这一份就跑通了：[`expected/report.md`](expected/report.md)** —— 那是一轮真实的运行结果。

---

## 先说你原本要手动做的事

北京时间 11:50，你有 3 个在投账户、10 个广告组。你要：

1. 逐个看花费 / 展示 / 点击 / 转化，手算 CPA、CTR、CVR、预算利用率；
2. 判断哪些该加预算、哪些该停、哪些**样本还不够所以不能判**；
3. 回想哪些组昨天已经被自己改过 —— 别把人工改动覆盖掉；
4. 改完之后确认平台**真的改上了**（而不是以为改上了）；
5. 写一页日报。

这套东西把这 5 件事全部做完，并且**在每一步都留下可回读的凭据**。

## 跑完你会拿到什么

数字全部来自 [`expected/summary.json`](expected/summary.json)（一轮真实运行）：

| 结果 | 数量 | 说明 |
|---|---|---|
| 发现总数 | **16** | 覆盖 **12 类判据**（见下表） |
| 可直接执行 | **4** | 且只发差异字段，不是整对象重写 |
| 已满足（跳过不写） | **1** | 目标值已就位 —— 再写一次是无意义的 significant edit，会重置学习期 |
| 冲突隔离 | **1** | 出方案期间有人改过这一行 —— 只隔这一行，其余照常 |
| 未知（先补证据） | **1** | 写前状态没读到 —— **缺失不等于相等，绝不放行** |
| 仅建议（不涉及写入） | **9** | 素材级发现与账户级信号，单独计数 |
| 模拟写入对象 | **4** | `daily_budget` 与 `status` 字段级 patch |
| 写后核对 | 4 条 → **3 生效 / 1 未生效** | 抓出一次「填了但没生效」 |
| 平台调用 | **0** | 全程离线 |

### 12 类判据分别是什么

```
LADDER_PROMOTE      4   晋级（原组预算 ×2）
TEST_UNDERTESTED    2   样本不足 / 花不动 —— 只记录，不判好坏
TEST_STOP_NOCONV    1   零转化过样本关且过止损线 —— 暂停复核
TEST_STOP_OVERCOST  1   超过目标成本 —— 暂停复核
CREATIVE_BREAKER    1   单条素材吃掉组内近半花费且成本超标 —— 熔断该素材，不动整组
CREATIVE_FATIGUE    1   频次/CTR/CVR 三条同时恶化 —— 判衰竭
CREATIVE_OVERFLOW   1   组内素材 9 条超硬上界 8 —— 先裁剪再扩量
AD_STATUS           1   effective_status 已 DISAPPROVED —— 走素材恢复，不重复改状态
LINK_OR_TRACKING_BAD 1  链接有效性未通过 —— 立即暂停，不等观察期
ACC_STOPPED         1   没有任何配置为在投的广告组 —— 断档还是暂停尾巴
ACC_NO_DELIVERY     1   配置在投但当日零消耗
ACC_BALANCE_LOW     1   余额低于警示线
```

## 三个「真实环境里最容易吃亏」的地方

这三条是**这套东西与「写个脚本算算数」的真正差别**。每条都能在 [`expected/report.md`](expected/report.md) 里找到对应行。

### ① 样本不够时，它拒绝下结论

`fictional-adset-a2`：花了 $3.10、180 次展示、0 转化。
`fictional-adset-a3`：花了 $15.30、420 次展示、0 转化。

看数字 a2 更"差"（转化率一样是 0）。但引擎给的是：

| 组 | 判定 | 给出的理由 |
|---|---|---|
| a3 | `TEST_STOP_NOCONV`（P0 暂停） | 展示 420 **过了判死门槛 300**，且花费 15.30 **过了止损线 14.12** |
| a2 | `TEST_UNDERTESTED`（只记录） | 展示 180 **未过门槛** ⇒ 样本不足，不得判素材好坏 |

再加一条：`fictional-adset-a5` 的 CPA 只有 $1.60（远好于目标 $4.71），但预算利用率 32% ⇒
引擎判的是 **「花不动，先解决能不能花的问题」**，而不是「这个组很好，加预算」。

### ② 它不相信「我改过了」

`fictional-adset-a6` 这组被判定晋级，预算 20 → 40。

写后回读时它读到的还是 **20.00**，于是：

> **未生效** — 写后回读与目标不一致 ⇒ 视为未真正生效，不要按已执行推进下一档：`daily_budget`：期望 40.00，实读 20.00

**这条行继续挂着**（`open_rows: 1`），不会被悄悄当成已完成。

### ③ 它不覆盖你手上的改动

`fictional-adset-a9` 方案里是 10 → 20。但复拉写前状态时读到的是 **30.00**（有人在出方案期间改过）。

引擎没有覆盖，也没有让整批重做 —— 它把这一行单独拎出来：

> **冲突隔离** — `daily_budget`：现值 30.00 既非基线 10.00 也非目标 20.00 ⇒ 人工改过，隔离该行。

同批其余 15 条照常判定、照常执行。需要人处理的只有 **2 条**（1 条冲突 + 1 条未知）。

## 跑起来

```bash
python3 demo/run_demo.py            # 跑一轮并把回执打到终端
python3 demo/run_demo.py --check    # 校验 expected/ 与真实新跑结果是否一致
python3 demo/run_demo.py --refresh  # 从一次真实运行重新生成 expected/
```

跑完的产物落在 `demo/out/`（已被 gitignore）：

| 文件 | 内容 |
|---|---|
| `findings.json` | 每个广告组的指标 + 全部发现（带证据） |
| `gate.json` | 逐条写前闸门结果 + 只含可写字段的写计划 |
| `application.json` | 本次记入台账的事件 |
| `reconciliation.json` | 写后逐条核对 |
| `ledger.jsonl` | 只追加的台账（跨轮累积，状态由事件折叠得出） |
| `report.md` | 一页回执 |
| `round-summary.json` | 机器可读摘要 |

## 这个文件夹里有什么

| 路径 | 作用 |
|---|---|
| `README.zh-CN.md` | 你正在读的这份：为什么值得看、跑完能得到什么 |
| `README.md` | 同样的内容，英文 |
| `run_demo.py` | 一条命令跑通，并负责 `expected/` 的生成与漂移校验 |
| `expected/report.md` | **一轮真实运行的回执**，不用跑就能看 |
| `expected/summary.json` | 同一轮的确定性摘要（闸门计数、写计划、核对结果） |

引擎本身仍在仓库约定的位置（根目录 `operating_rules.py` / `operating_loop.py`），
fixture 在 `examples/operating/`。这个文件夹是**展示层**，不复制逻辑 ——
唯一的职责是让「能实现什么」一眼可见，并且用 `--check` 保证提交进来的样例**永远不会与代码脱节**。

> 为什么要有 `--check`：一份比代码说得更多的样例，比没有样例更糟。
> CI 里挂了这一步，样例一旦漂移就会红。

## 它刻意不做什么

- **不连接任何平台、不持凭据、不写任何账户。** 输出是给人审阅的动作清单，不是已执行的指令。
- **不读素材内容。** 素材只按声明的身份被引用。
- **不自动决策。** 每条规则都产出带证据的建议，闸门和人始终在路径上。
- **不宣称结果可推广。** 规则触发不等于证明了原因；修好了一行也不等于证明了修法有效。
