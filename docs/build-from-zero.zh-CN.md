# 怎样把投放工作搭成一个 Agent

[English](build-from-zero.md) · [看可运行的巡检示例](../demo/README.zh-CN.md)

这套 Agent 把接账户、整理业务、选素材、配方案和核对结果串起来，让投手把时间放在分析与决策上。它来自已经在 Agent 工具中使用的投放工作流；其他人可在自己的宿主中加载说明，配合已有授权工具开展工作。下面用一个虚构例子讲清楚怎样搭建和交接。

## 先认识这个例子

**以下业务、素材、预算和数据全部虚构，仅用于讲解搭建顺序。** 它与 [demo](../demo/README.zh-CN.md) 中可运行的账户巡检数据是两套例子。

假设你有一个面向美国成人的在线英语课程网站，想通过广告获得 **15 分钟试听预约**。用户看完广告，进入预约页，成功提交表单；销售之后再确认预约是否有效。

你准备先用一个 Meta 账户，提供三条英文视频。本轮测试总预算是 **60 美元**，约定 **3 天后一起复盘**。这些都是本例用户的选择，不是通用推荐值。

整条搭建路线是：

**接账户 → 了解业务 → 确定做法 → 处理每天工作 → 保存确认过的经验。**

下面说明宿主怎样组织一轮工作。能否实际读取、查看素材和发布，由该宿主的工具、账户与授权决定，部署者需逐项验收。文末另列 Python 离线程序的范围；本例对话和数字不是实盘证明。

## 1. 接账户：先确认能用什么

你告诉 Agent：“先做 Meta，用课程业务的这个账户，TikTok 和 Google 以后再说。我已经有一个连接工具。”

Agent 先确认账户身份、能否读到广告和数据、能否配置对象，以及修改后能否核对结果。已有连接可以继续用；没有连接时再帮助选择接入方案。

**这一阶段交给你的结果应该很具体：**“本次只使用课程账户 A；广告读取可用；配置权限还缺一项，先补齐后再继续。”不把“工具已安装”当成账户已接通，也不急着给你一整张业务问卷。

搭建完整投放流程时，把连接检查放在入口。以后换平台或账户，再检查新范围，不把整套业务访谈从头重来。如果当前只要日报，读取能力足够即可开展，不必先补发布权限。

## 2. 了解业务：把‘我想获客’说清楚

所需接入能力确认可用后，Agent 从已有介绍中整理背景，再问真正影响方案的问题。例如：

> “这轮把成功提交表单算作转化，还是销售确认有效后才算？免费试听后怎样收费？60 美元是整轮预算还是每天预算？”

你确认：本轮先看提交表单的成本，同时单独记录有效预约数；试听后销售课程；60 美元是整轮总额。暂时不知道每位学员长期能带来多少收入，就保留未知。

**Agent 输出一份能纠正的业务摘要：**美国、英语、课程网站、成人学员、试听预约、表单提交与有效预约两个口径、60 美元总预算、3 天后复盘。

这份摘要以后随任务复用。换成 App 或电商，重新补齐下载、购买、收入等对应信息，而不是继续沿用课程预约的定义。

## 3. 确定做法：同样三条素材，两类用户走不同引导

你提供视频和制作说明：

| 素材 | 内容 | 制作说明确认的差异 |
|---|---|---|
| A | “开会时不敢用英语发言？”开头，随后介绍试听 | 作为本轮参照素材 |
| B | “用 15 分钟练一次工作英语对话”开头 | 与 A 同一概念，只有开头不同；主体、行动提示和预约页相同 |
| C | 老师示范怎样回答一个工作问题 | 与 A 不同概念，仍进入同一个预约页 |

**如果你是新手：**Agent 先给两个能比较的候选：“选 A 和 B，看看不同开头的差异；或选 A 和 C，先比较两种内容方向。”它解释各自固定什么、能回答什么问题，再让你选择。

**如果你是熟手：**你可以说：“按我现有的方法，先比较内容方向，预约页不变，A 做参照。”Agent 据此整理 A 和 C 的方案，并核对指标和观察期。若还要求满足条件后加预算，须写清触发条件、额度和授权边界，并检查本宿主能否执行；做不到就留下具体缺口。不能为了符合某个模板，悄悄删去这条要求。

下面沿用用户确认 A 和 B 的这条路线。**Agent 给出的选择理由是：**A 是你指定的参照，B 符合只改开头的条件，C 因为概念也变了而不进入本轮。如果采用 A 和 C，后面的工作步骤相同，但选材依据换成比较内容方向。本例依据你确认的制作说明；若宿主实际查看过画面或视频，应另外记录查看范围与发现。不能仅凭说明声称已经看过素材。

方法需要你确认采用；选出素材也不代表它们已经被证明会跑得好。这两种比较只是本例可选方法，宿主工作流不限制用户只能采用它们。Python 编译器目前只支持这两类结构化模板，其他条款保留给宿主按能力处理。

## 4. 处理每天工作：把准备、判断和核对分开

先准备一份整批审阅单：

- 本轮只用课程账户 A，面向美国，使用 A、B 两条素材和同一预约页。
- 每个测试单元一个素材，本轮总额不超过用户给定的 60 美元；根据原生结构说明预算放在哪个对象、是日预算还是总预算、是否共享，不承诺两条素材各花一半。
- 看表单提交成本，并保留销售确认的有效预约数；3 天后一起复盘，不因到了日期就自动宣布胜出。

**你的决定是确认或修改这份具体方案。** 宿主核对账户和工具能力、记录本批授权范围后，连续完成获准的配置与发布步骤。创建暂停对象也属于写入，应在确认范围内；没有变化的已获准机械步骤不必逐条再问。若工具缺少所需能力，就交付准备结果并列出缺口，不能把本地模拟当成发布。

交接时，例如“已创建并核对 A/B 的配置；A 已通过审核，B 仍待审”，应以对应对象、时间和读取结果为依据。配置启用、审核通过和实际获得展示分别记录，不给整个批次统一写一个成功状态。

假设后来提供的一天数据如下，仍然只是虚构观察：

| 素材 | 花费 | 提交表单 | 每次提交成本 |
|---|---:|---:|---:|
| A | 18 美元 | 3 | 6 美元 |
| B | 12 美元 | 1 | 12 美元 |

Agent 可以整理出“本日 A 的表单提交成本较低；有效预约结果未齐，还不能据此认定 A 更值得扩量”，把数据、缺口和建议放在一起。你决定继续观察或调整方向，Agent 不把一句“看起来不错”变成自动加预算。

同样，准备改配置时若发现当前预算与原记录不同，应先核对差异；操作后的值与计划不符，就保留为待处理，不能只凭成功提示写成已完成。回执里的实际状态必须来自读取结果，不能把计划目标或写死的 `ACTIVE` 填进去。

以后你只说“按课程业务出昨天的日报”，Agent 沿用已知口径，核日期、时区、账户和数据覆盖即可，不必重问怎么测 A/B；开始新一轮巡检时则先回验相关的上一轮待办。

## 5. 保存经验：确认什么，才复用什么

复盘时你补充：“以后这个课程项目都要把表单提交和有效预约分开，别只按表单成本决定扩量。”

Agent 把它整理为待确认的工作约定，写明适用于这个课程产品、为什么提出、还有哪些结果未知。**你确认保存后，后续任务才复用这条约定。**

如果下一次要从“比较开头”改为“比较内容方向”，Agent 应重新列出变化：素材从 A/B 换成 A/C，固定项和本轮问题随之调整。你确认新做法，再准备新计划。

经验积累就是这样逐步发生的：保留观察、提出候选、用户确认、以后复用或修订。采用某条约定与证明它有效是两件事；一次结果不自动变成所有产品的规则，也不会扩大 Agent 的执行权限。Python 程序没有自行学习并晋升经验的能力。

## 当前仓库与这条路线的关系

| 层次 | 与这个例子的关系 |
|---|---|
| Agent 工具中的历史业务实践 | 素材审查、建单、报表与巡检已有使用记录，见[脱敏案例](case-studies.zh-CN.md)；本课程例子仍是虚构 |
| 可复用宿主工作流 | 宿主负责交流，并使用已连接、已获准的工具读取、查看素材、配置和核对；部署者按具体环境验收 |
| 公开 Python 程序 | 可离线保存业务资料/私有记录、生成两类方法候选、按声明差异准备测试计划、分析快照和模拟恢复；没有平台调用、媒体理解或自动学习 |

先按[宿主工作流](workflow.zh-CN.md)和[任务模板](../templates/task-record.zh-CN.md)完成自己的任务。需要验证受支持的结构化计划时，再选用 Python；无需把每项日报、排障或迁移都转换成 `task.py` 的素材测试。具体限制与验收见[能力范围](capability-status.zh-CN.md)。

可复用的部分是业务资料、经确认的方法、准备与核对步骤；产品、国家、预算和具体做法由用户决定。连接层、业务方法和执行记录分开，方便分别更新，而不是让所有用户照抄同一套投法。
