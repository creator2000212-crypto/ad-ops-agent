# 让 Agent 了解你的业务和合作方式

[English](first-run.md) · [首次使用](first-check.zh-CN.md) · [日常任务工作流](workflow.zh-CN.md)

**适合谁：**已经完成本次账户连接检查，想让 Agent 按自己的业务和方法工作的人。**读完得到什么：**一份可核对的业务摘要、当前任务和缺项清单；你通过对话提供信息，无需填写程序配置。

如果还未打开项目或核对连接，从[第一次使用](first-check.zh-CN.md)开始。这里沿用已验证的账户、工具和已提供资料，不重新安装连接器或重复整套问卷。分析已有报表时，先核对报表来源和范围；无需为这类任务申请广告写权限。

## 1. 确认本次能做什么

先由 Agent 说明本次选定的平台、账户和实际可用能力。只读任务需要读取或报告能力；首次完整配置与发布流程，需要先核对必要的读取、写入及操作后重新读取对象的能力，再进入完整业务交流。无需接齐未选中的平台或账户，也不通过创建广告来探测权限。

缺少能力时，Agent 说明受影响的步骤和下一步接入操作。已提供的资料继续保留，现有能力支持的独立工作可以继续。尚无连接且未选择路线时，可优先了解 [Pipeboard](https://pipeboard.co/#via=tian)；已有 MCP、API、SDK 或其他连接方案可以继续使用。具体选择与设置集中在[接入指南](platform-connectivity.zh-CN.md)。

连接成功不代表已经授权发布或花费预算。真实能力以账户读取、工具能力和权限证据为依据；公开 Python 的离线结果不能替代它。项目使用范围见[能力状态](capability-status.zh-CN.md)。

## 2. 用三个问题确定合作方式

Agent 先复用已有信息，只问尚不清楚的部分；第一次最多提出三个相关问题。

| 需要了解什么 | 通俗问法 | 回答怎样影响后续工作 |
|---|---|---|
| 当前进展与需求 | “你已经在投放了吗？这次最想完成哪件事？” | 区分投放准备、已有账户分析或具体操作任务 |
| 当前平台经验 | “你之前在这个平台做过投放吗？” | 决定术语解释深度；不知道也可继续 |
| 合作方式 | “希望我带你梳理方案，还是沿用你的方法或 SOP？” | 提供可选方案，或保留并核对现有方法 |

经验按平台区分，合作方式可以随任务改变。熟悉 Meta 的投手第一次使用 Google Ads，也可以要求详细引导；资深投手不需要先懂程序或配置文件。

**没有成熟方法时，可以这样说：**

> 账户已经连接。我有一个课程网站，想获取预约客户，但没有成熟投放方法。请先了解我的产品、市场、预约流程和现有素材，只追问影响下一步的缺项。先给我业务摘要、准备清单和可选测试方向，预算由我确认。

Agent 解释选择及其适用条件，提出候选方案。尚未确认的建议保持为候选，不记录成用户已经采用的方法。

**已有方法时，可以这样说：**

> 账户已经连接。请读取我提供的 SOP，整理必须保留的规则、允许变化的部分、观察条件和缺失信息，再核对当前工具能否支持。保留我的方法，先给出可审阅的执行安排，暂不修改账户。

Agent 保留原文和来源，标出冲突、缺项与当前工具不支持的要求，再由用户决定如何处理。用户方法可以覆盖日报、巡检、素材测试或其他任务，不限于公开 Python 的两类测试模板。

## 3. 只补齐本次任务需要的背景

这些是按需使用的提示，不是一份必须从头填完的问卷。接口能读取的事实由 Agent 查询并注明来源；业务含义、目标与取舍由用户说明。已有信息不重复问，未知不猜填。

| 当前任务 | 用户需要说明 | Agent 读取、整理和核对 | 本次先交付什么 |
|---|---|---|---|
| 有产品，尚未投放 | 产品、市场、目标客户、转化流程、已有素材；预算边界未定可保留待确认 | 网站或 App 目的地、可用账户与事件、资料缺项 | 业务摘要、准备清单、候选测试方向 |
| 查看已有投放 | 账户与时间范围、想回答的问题、已采用的指标或方法 | 报表、时区、币种、数据覆盖和口径 | 有来源的现状分析、建议与待确认项 |
| 按现有 SOP 工作 | SOP 原文或文件、适用范围、本次任务与不可改变的条件 | 规则与工具对应关系、当前对象、冲突与缺项 | 方法复述、可执行范围和批次草案 |

产品表面不同，需要补充的背景也不同：

- **网站业务：**用户从广告进入哪个页面，什么算转化；表单提交是否还要经过销售确认才算有效线索。
- **App 业务：**推广哪个商店页面、操作系统和应用内事件；收入来自广告（IAA）、应用内购买（IAP），还是两者都有。
- **涉及收入判断：**收入数据来自哪里、看多长时间、是否扣除退款；指标名称相同不代表统计口径相同。
- **涉及素材测试或写入：**本次要比较什么、保持什么不变、哪些素材可用、预算是总额还是每日额度，以及观察或调整条件。未确定的写入条件会留在草案中，不由 Agent 默认补齐。

这些信息只在影响当前任务时追问。仅分析昨天的现有报表，不必重新制定整套素材策略。

## 4. 核对一份业务摘要，再开始任务

下面是**虚构课程网站示例**，用于展示交付形式；不是实际账户记录或推荐预算。

> **本次任务：**准备首次素材测试方向，暂不修改账户。
>
> **已知业务：**面向美国成年用户的英语课程网站；希望用户预约 15 分钟体验课。
>
> **已有资料：**三条视频素材；用户尚无固定测试方法。
>
> **需要区分的结果：**表单提交、有效预约和后续付费分别记录，不能互相替代。
>
> **候选方向：**比较同一卖点的不同开头，或比较不同卖点；先核对素材内容后再确定。
>
> **待确认：**有效预约的定义与数据来源、可用转化事件、预算类型与上限、观察条件。
>
> **接下来：**用户确认或修正摘要；Agent 根据已确认条件整理素材与方案。未定条件保留在草案里。

| 谁负责 | 应完成什么 |
|---|---|
| 你 | 补充无法从账户得知的业务信息，修正摘要，决定目标、方法和资金边界 |
| Agent | 读取允许访问的资料，标明来源，区分事实、候选判断和未知，整理摘要与缺项 |
| 你与 Agent | 确认本次任务范围，确定哪些缺项影响下一步，进入对应工作流 |

**完成标志：**双方能说清本次做什么、使用哪些已确认信息、还有哪些缺项，以及先交付什么。业务摘要和方法选择不会自动授予发布权限。准备具体写入批次后，核对已有授权或补齐缺少的确认，再执行并读回；只读任务直接交付报告。

下一步按任务进入[日常任务工作流](workflow.zh-CN.md)。想先看完整业务过程，可阅读[课程网站示例](build-from-zero.zh-CN.md)；需要代码接口时才继续下面的开发者附录。

## 开发者附录：离线配置字段与示例

普通使用者可跳过本节。宿主负责把对话整理成私有输入；下面是公开 Python 的离线契约，不是宿主真实工具的统一门槛。

### 接入偏好与模拟能力

`setup_preferences.route` 保存 `undecided`、`pipeboard`、`existing`、`self_managed` 或 `other_mcp`；`setup_preferences.recommendation_dismissed` 保存是否关闭推荐。已有路线或关闭推荐后不重复主动推荐。选择路线不构成接入成功证据。

`onboarding.py` 的 `connection_gate` 对四类 readiness 检查模拟读取与 `create_simulated_draft` 能力；未通过时 `guidance` 保持接入阶段。该契约没有变更，不要求真实只读任务也具备写入权限；`ready_simulation` 不是真实账户验收。

### 协作字段

```json
{
  "experience_by_platform": {"meta": "new", "tiktok": "unknown", "google": "unknown"},
  "approach": "guided",
  "current_need": "为第一个产品准备素材测试方案",
  "explanation": "detailed"
}
```

以上对象保存在 profile 的 `collaboration` 中。经验值为 `new`、`experienced`、`unknown`；方式为 `guided`、`bring_own`、`undecided`；说明详略为 `detailed` 或 `concise`。离线协作门槛要求明确方式和非空当前需求；经验可未知。Python 按方式分流问题并记录偏好，未实现完整的自适应对话界面。任何字段都不扩大账户、预算或发布权限。

M2 是可选的离线方法编排模块，仅编译单变量钩子比较和概念探索。M1 私有文本方法用于背景与审阅，不会自动变成已采用的 MethodSpec。宿主真实工作不必经过 M2；接口与约束见 [Python 方法编排参考](method-planning.zh-CN.md)。

### 查看一次故意缺项的检查

在仓库根目录运行：

```bash
python3 onboarding.py --input examples/onboarding-setup-required.json --out runs/setup
```

此虚构输入缺少连接，**退出码 `2` 是预期结果**。打开 `runs/setup/setup.md` 看引导，`runs/setup/setup.json` 看结构化结果，`runs/setup/context.json` 看 `connection_gate` / `guidance`。不要修改成功字段来宣称真实接入完成。

`examples/onboarding-learning.json` 是完整虚构档案；`examples/onboarding-app-hybrid-discovery.json` 保留业务缺项。`python3 scripts/demo.py` 检查新生成的虚构输入；方法候选、确认和恢复演示见 [Python 方法编排参考](method-planning.zh-CN.md)。所有示例均不读取真实账户，也不证明跨宿主真人可用性。
