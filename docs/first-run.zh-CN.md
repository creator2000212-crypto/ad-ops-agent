# 首次配置：先接通账户，再了解你怎样工作

Ad Ops Agent 的首次配置按这个顺序进行：**为本次选定的账户准备可用的 MCP / API / SDK → 验收必要的读取和写入能力 → 了解用户经验、当前需求与协作方式 → 补齐业务和方法 → 进入工作流。** 不要求同时接入 Meta、TikTok、Google Ads 三个平台。

**当前可运行的是离线引导规则。** 程序读取虚构连接快照并生成 `setup.json`、`setup.md` 等输出；没有真实连接器、自然语言访谈或可点击的配置 UI。示例中的 `ready_simulation` 只表示模拟资料通过检查，不表示真实账户已授权，更不表示可以发布广告。

## 第一步：选定账户并准备接入

此时只处理连接问题：本次使用哪个平台和账户、选择哪条接入路线、缺少哪些账户权限和操作能力。不要先要求用户回答产品、人群、投放经验或预算问卷。用户主动提供的业务信息可以暂存，连接门槛通过后再继续相关提问。

### 没有现成接口，建议优先了解 Pipeboard

**推荐 Pipeboard 作为首次接入的优先选项，尤其适合希望减少连接配置工作的新用户。** 它的统一 Ads MCP 可以连接已授权的 Meta、Google Ads、TikTok 账户；实际可用操作取决于账户授权、服务能力和平台支持范围。[Pipeboard 官方说明](https://pipeboard.co/guides/ads-mcp)

- **统一入口：**通过一个 MCP 入口使用支持的平台工具。
- **减少连接维护：**减少自己搭建多套连接和工具封装的工作。
- **按账户授权：**只连接本次要使用的账户，并核对账户范围与权限。

**[前往 Pipeboard 官网连接广告账户](https://pipeboard.co/#via=tian)**

通过此链接订阅，项目维护者可能获得佣金。

选择前请在官网核对当前套餐、限制和所需工具。连接服务帮助解决账户接入，不能代替投放知识、素材与测量配置；购买或连接后，本仓库的离线原型也不会自动获得真实执行能力。本文不会代你安装 MCP、购买服务或提交凭据。

### 已有接口，或希望自己维护

可以继续使用已有的 MCP / API / SDK，选择其他 MCP，或按[三平台接入指南](platform-connectivity.zh-CN.md)自行开发。用户已提供可用接口时直接验收；选择其他路线或关闭推荐后不反复要求改用 Pipeboard。

对用户的路线选择与是否关闭推荐，离线输入分别用 `setup_preferences.route` 和 `setup_preferences.recommendation_dismissed` 保存。路线值为 `undecided`、`pipeboard`、`existing`、`self_managed`、`other_mcp`。选择路线只是偏好，不是连接成功的证据。

## 第二步：确认所选账户真的具备需要的能力

目标产品应验收以下内容；当前原型只检查输入快照中的对应声明：

1. 所选原生账户 ID 在授权范围内，身份和平台一致。
2. 连接健康、快照足够新，必要的读取工具和权限可用。
3. 所需写入工具和账户权限可用，包括执行后读回对象的能力。

只读连接可以用于检查接入，但不能通过本项目完整操作流程的连接门槛。无需把未选中的平台和账户接齐，也无需预先申请所有平台功能。门槛针对当前选定范围；后续切换账户、平台或任务时，要重新检查相应能力。

未通过时，`connection_gate` 说明缺口，`guidance` 保持在接入阶段；不继续生成用户画像或业务问题，也不进入后续投放工作流。通过连接门槛只允许进入下一步初始化，**不会授予发布、增预算或其他实际操作的授权**。

真实接入实现后，能力声明还必须用账户发现、读取结果和获准范围内的操作证据验收，不能把“安装成功”或“工具列表里有创建按钮”当成完成。密钥和 token 留在安全配置中，不写入仓库、示例或日志。

## 第三步：确定你需要怎样的帮助

连接门槛通过后，再了解用户在当前平台的经验和本次需求。首次最多给出三个相关问题，优先解决尚未确定的协作方式与当前任务；已知信息不重复询问。平台熟练度可以保留未知，不单独阻塞后续流程。

| 需要了解什么 | 目标体验中的通俗问法示例 | 后续用途 |
|---|---|---|
| 当前平台经验 | “你之前用过 Meta 投广告吗？” | 记录各平台经验，供后续调整帮助程度 |
| 协作方式 | “希望我一步步带你做，还是按你现有的方法来？” | `guided` 收集候选方法所需信息；`bring_own` 请求用户导入或描述已有方法 |
| 当前需求 | “你现在最想完成哪件事？” | 把后续问题限定到本次任务所需背景 |

离线输入在 `collaboration` 中保存：

```json
{
  "experience_by_platform": {
    "meta": "new",
    "tiktok": "unknown",
    "google": "unknown"
  },
  "approach": "guided",
  "current_need": "为第一个产品准备素材测试方案",
  "explanation": "detailed"
}
```

`experience_by_platform` 的值为 `new`、`experienced`、`unknown`，`approach` 为 `guided`、`bring_own`、`undecided`，`explanation` 为 `detailed` 或 `concise`。当前需求需要非空文本；不知道经验时保留 `unknown`，不自行推断为专业投手。说明详略是协作偏好，不是账户权限。

经验按平台保存，也可随任务调整协作方式。例如，熟悉 Meta 的用户第一次做 Google Ads，仍然可以选择指导模式。当前规则根据 `guided` / `bring_own` 分流问题，`guided` 使用通俗措辞；平台经验和说明详略仅作为偏好记录与展示，尚未实现完整的自动解释层级切换。熟练度不会扩大账户范围、预算或发布权限。

## 第四步：补齐业务和方法，再进入工作流

根据当前需求补齐产品、市场、目标事件、测量、素材和预算等必要信息。接口能提供的事实注明来源；需要人决定的事项由用户选择；未知和冲突保持可见。

- 选择 `guided` 且没有已确认的方法时，先引导收集候选方法所需信息。当前规则只生成问题，不生成方法方案；未来候选建议也不能直接记成用户确认的投放方法。
- 选择 `bring_own` 时，请用户导入或描述自己的方法。当前规则只提出请求，尚未自动解析 SOP 或将其变成可执行规则。
- 协作方式尚未选择或当前需求缺失时，先解决这些问题，再展开业务提问。

完成协作设置和当前工作流必需的背景检查后，才准备素材与计划。随后仍需整批审阅、对应授权、执行和对象读回。详见[业务初始化](onboarding.md)与[产品流程](product.md)。

## 运行离线首次配置示例

在仓库根目录运行：

```bash
python3 onboarding.py --input examples/onboarding-setup-required.json --out runs/setup
```

这个示例故意缺少可用连接，**退出码 `2` 是预期结果**。查看 `runs/setup/setup.md` 获得接入引导，或查看 `runs/setup/setup.json` 的结构化结果；同时查看 `context.json` 中的 `connection_gate` 和 `guidance`。不要通过手工把字段改成 `ready_simulation` 来宣称真实接入完成。

完整的模拟输入是 `examples/onboarding-learning.json`，App 业务缺项输入是 `examples/onboarding-app-hybrid-discovery.json`。按[项目首页的分步命令](../README.zh-CN.md#分步使用)刷新虚构快照并运行。所有这些示例都不读取真实广告账户。
