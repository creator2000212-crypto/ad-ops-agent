# 首次配置：先接通账户，再了解你怎样工作

[English](first-run.md) · [宿主工作流](workflow.zh-CN.md)

首次先明确本次要做什么、使用哪些平台和账户。**完整配置与发布流程按“接入 MCP / API / SDK → 验收必要读取、写入和读回能力 → 明确协作方式 → 补齐业务与方法 → 准备、审阅并执行”推进。** 不要求同时接入三个平台。只读分析任务只检查所需读取与报告能力；已有报表的分析不要求额外申请广告写权限。

**宿主工作流与公开 Python 分开使用。** 基于 Agent 工具的工作流已用于作者业务；在 Codex 等新宿主中仍应验证本次可用工具和账户范围。已有工具通过能力验证且操作获准后，宿主可以直接开展真实业务，不必先实现 Python 适配器。公开 Python 读取结构化档案与模拟快照，提供离线引导、两类方法编译和模拟恢复；它不连接真实平台。`ready_simulation` 只表示模拟资料通过检查。具体范围见[能力状态](capability-status.zh-CN.md)。

要让 Codex 等宿主在实际对话中遵循本流程，需要加载仓库根目录 [AGENTS.md](../AGENTS.md)。具体见[宿主加载与对话验收](use-in-agent.zh-CN.md)；Python 推荐卡与宿主对话是两个不同入口。

## 第一步：选定账户并准备接入

此时先处理任务所需的连接问题：本次使用哪个平台和账户、是否已有可用路线、缺少哪些权限和操作能力。完整投放初始化不先抛出产品、人群或预算问卷。用户主动提供的业务信息可以保留，所需连接通过后再继续提问；已提供数据的分析先确认数据范围、口径和来源。

### 没有现成接口，建议优先了解 Pipeboard

**推荐 Pipeboard 作为首次接入的优先选项，尤其适合希望减少连接配置工作的新用户。** 它的统一 Ads MCP 可以连接已授权的 Meta、Google Ads、TikTok 账户；实际可用操作取决于账户授权、服务能力和平台支持范围。[Pipeboard 官方说明](https://pipeboard.co/guides/ads-mcp)

- **统一入口：**通过一个 MCP 入口使用支持的平台工具。
- **减少连接维护：**减少自己搭建多套连接和工具封装的工作。
- **按账户授权：**只连接本次要使用的账户，并核对账户范围与权限。

**[前往 Pipeboard 官网连接广告账户](https://pipeboard.co/#via=tian)**

选择前请在官网核对当前套餐、限制和所需工具。连接服务帮助解决账户接入，不能代替投放知识、素材与测量配置。宿主使用连接后的实际工具能力；购买服务不会给 Python 程序增加真实执行功能。推荐本身不代表用户已授权安装、购买或提交凭据。

### 已有接口，或希望自己维护

可以继续使用已有的 MCP / API / SDK，选择其他 MCP，或按[三平台接入指南](platform-connectivity.zh-CN.md)自行开发。用户已提供可用接口时直接验收；选择其他路线或关闭推荐后不反复要求改用 Pipeboard。

对用户的路线选择与是否关闭推荐，离线输入分别用 `setup_preferences.route` 和 `setup_preferences.recommendation_dismissed` 保存。路线值为 `undecided`、`pipeboard`、`existing`、`self_managed`、`other_mcp`。选择路线只是偏好，不是连接成功的证据。

## 第二步：确认所选账户真的具备需要的能力

宿主按本次任务验收以下内容；Python 离线示例仅检查快照中的对应声明：

1. 所选原生账户 ID 在授权范围内，身份和平台一致。
2. 连接健康、快照足够新，必要的读取工具和权限可用。
3. 若本次包含配置或发布，所需写入工具和账户权限可用，包括执行后读回对象的能力。

只读连接可用于账户盘点、报告与诊断，不能代替写入流程需要的能力。无需把未选中的平台和账户接齐，也无需预先申请所有平台功能。门槛针对当前任务；切换账户、平台或操作时重新检查相应能力。

宿主发现缺口时说明受影响步骤，继续当前能力允许的独立工作，不把缺写权限扩大成无法分析已有数据。首次完整写入流程的必要能力未通过时，先解决接入，不提前展开业务问卷。通过能力验收**不会授予发布、增预算或其他实际操作的授权**。

真实能力用账户发现、读取结果、工具 schema 和权限证据核对；获准操作后再保存执行及读回证据。不能把“安装成功”或存在一个创建工具当作完整验收，也不为探测权限擅自创建广告。密钥和 token 留在安全配置中，不写入仓库、示例或日志。

公开 `onboarding.py` 的 `connection_gate` 仍对四类 readiness 统一检查模拟读取与 `create_simulated_draft` 能力；未通过时 `guidance` 保持接入阶段。这个离线契约没有变更，不作为宿主只读任务的统一前置门槛，也不能用手工填写的成功快照替代真实验证。

## 第三步：确定你需要怎样的帮助

连接门槛通过后，再了解用户在当前平台的经验和本次需求。首次最多给出三个相关问题，优先解决尚未确定的协作方式与当前任务；已知信息不重复询问。平台熟练度可以保留未知，不单独阻塞后续流程。

| 需要了解什么 | 目标体验中的通俗问法示例 | 后续用途 |
|---|---|---|
| 当前平台经验 | “你之前用过 Meta 投广告吗？” | 记录各平台经验，供后续调整帮助程度 |
| 协作方式 | “希望我一步步带你做，还是按你现有的方法来？” | `guided` 收集候选方法所需信息；`bring_own` 请求用户导入或描述已有方法 |
| 当前需求 | “你现在最想完成哪件事？” | 把后续问题限定到本次任务所需背景 |

离线输入在 `collaboration` 中保存：

```json
{
  "experience_by_platform": {
    "meta": "new",
    "tiktok": "unknown",
    "google": "unknown"
  },
  "approach": "guided",
  "current_need": "为第一个产品准备素材测试方案",
  "explanation": "detailed"
}
```

`experience_by_platform` 的值为 `new`、`experienced`、`unknown`，`approach` 为 `guided`、`bring_own`、`undecided`，`explanation` 为 `detailed` 或 `concise`。当前需求需要非空文本；不知道经验时保留 `unknown`，不自行推断为专业投手。说明详略是协作偏好，不是账户权限。

经验按平台保存，也可随任务调整协作方式。例如，熟悉 Meta 的用户第一次做 Google Ads，仍然可以选择指导模式。宿主根据用户回答调整解释深度；Python 规则只根据 `guided` / `bring_own` 分流问题，将经验和详略作为记录与展示，未实现完整的自动解释层级切换。熟练度不会扩大账户范围、预算或发布权限。

## 第四步：补齐业务和方法，再进入工作流

根据当前需求补齐产品、市场、目标事件、测量、素材和预算等必要信息。接口能提供的事实注明来源；需要人决定的事项由用户选择；未知和冲突保持可见。

- 选择 `guided` 时，宿主用通俗语言收集测试问题、素材和观察口径，提出可审阅的方法候选。用户明确选择、缺口补齐后才采用，不把建议记录为已经确认。
- 选择 `bring_own` 时，宿主保留现有方法的原文、来源、适用范围和固定条件。方法不限于 Python 的两类模板；逐项检查当前工具能否支持，缺口或冲突不静默删除。
- 协作方式尚未选择或当前需求缺失时，先解决这些问题，再展开业务提问。

用户通过对话工作，无需自行编辑 JSON。宿主展示变化项、固定项、范围、测量口径与未解决项，解释素材入选/排除理由和预算，再使用实际工具准备配置。需要可复验的离线方法检查时，宿主才整理输入并调用 `task.py`：M2 只编译单变量钩子比较和概念探索；M1 文本方法不能未经确认自动变成 MethodSpec。详见[方法确认与测试计划](method-planning.zh-CN.md)。

完成本次必要的背景检查后，准备素材与整批计划。核对已有授权或取得缺少的确认，再通过宿主工具执行并读回对象；超时或不一致先核实，不盲目重建。分析任务直接交付有来源的报告与建议，不额外触发发布。离线模拟仍只产生本地结果。详见[宿主工作流](workflow.zh-CN.md)与[业务初始化](onboarding.md)。

## 运行离线首次配置示例

在仓库根目录运行：

```bash
python3 onboarding.py --input examples/onboarding-setup-required.json --out runs/setup
```

这个示例故意缺少可用连接，**退出码 `2` 是预期结果**。查看 `runs/setup/setup.md` 获得接入引导，或查看 `runs/setup/setup.json` 的结构化结果；同时查看 `context.json` 中的 `connection_gate` 和 `guidance`。不要通过手工把字段改成 `ready_simulation` 来宣称真实接入完成。

完整的模拟输入是 `examples/onboarding-learning.json`，App 业务缺项输入是 `examples/onboarding-app-hybrid-discovery.json`。可运行 `python3 scripts/demo.py` 生成和检查当次虚构输入。所有这些示例都不读取真实广告账户。

要体验接入检查后的方法候选、确认、测试编译与模拟恢复，运行 `python3 scripts/demo_methods.py`。它覆盖虚构 App、电商、线索业务的两种协作方式；示例覆盖不代表跨宿主的真人可用性已经验证。
