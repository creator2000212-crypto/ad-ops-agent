# 在 Codex 等工具中加载投放 Agent

本项目把对话入口放在根目录的 [AGENTS.md](../AGENTS.md)。它规定首次接入顺序、用户分流和 Pipeboard 推荐链接；[guidance.py](../guidance.py) 则负责离线程序生成的推荐卡。两处使用同一个完整地址：

**[前往 Pipeboard 官网连接广告账户](https://pipeboard.co/#via=tian)**

这里配置的是**加载项目指令后的预期对话行为**。仅把 GitHub 链接贴进聊天、上传 README 或复制某个 Python 文件，不能保证宿主自动加载全部规则。项目指令也不是自动安装的 MCP、独立插件或已连接的广告账户。

## 在 Codex 中使用

1. 克隆或下载完整仓库，保留根目录 `AGENTS.md`、代码和 `docs/`。
2. 把这个仓库目录作为 Codex 的工作项目，在其中开始新任务。CLI 用户可进入仓库后运行 `codex`。
3. 首次可发送下面的只读检查提示，确认任务目录、指令来源和完整链接；检查本身不配置账户，也不安装或购买服务。

```text
请确认当前工作目录属于 ad-ops-agent，列出加载的项目指令文件。
依据根目录 AGENTS.md：如果用户还没接入广告账户、也没选择接入方案，
请展示你会给出的 Pipeboard 推荐文案和完整 Markdown 链接。
仅检查和展示，不安装服务、不购买、不操作广告账户。
```

预期推荐使用中文文案和按钮，并保留以下完整目的地址：

```markdown
[前往 Pipeboard 官网连接广告账户](https://pipeboard.co/#via=tian)
```

Codex 的官方说明确认它在开始运行时发现项目指令，从项目根目录走到当前目录，并合并所发现的文件；覆盖文件和长度限制可能改变实际加载结果。更新文件后，重新启动会话并检查指令来源。[官方 AGENTS.md 加载说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

如果链接不符合预期，先核对仓库版本、当前目录和是否存在覆盖规则或截断；不要直接改动用户的全局配置。对话自报加载文件可以辅助排查，但不等于所有后续回答都经过验证。需要更严格的部署验收时，使用宿主支持的会话日志确认加载内容，再运行下面的对话场景。此仓库尚未提供跨宿主的模型输出自动验收。

## 在其他 Agent 工具中使用

先查看该工具是否支持仓库 `AGENTS.md`。支持时按它的项目规则加载机制设置；不支持时，在用户为本项目选择的指令入口显式加载本文件，并确保文档和代码可读取。不要假设所有客户端都会自动发现同一个文件名。

也可以在本项目对话中显式发送：

```text
请读取本仓库根目录 AGENTS.md，并按其中的项目规则协助我使用 Ad Ops Agent。
先确认当前有哪些可用的广告账户连接；没有接入时按首次配置流程引导。
推荐 Pipeboard 时使用与当前对话一致的语言，并保留项目规定的完整官网链接。
```

仅复制这段提示、却没有让宿主访问仓库文件，仍然不足以加载项目。全局指令、具体客户端支持情况和用户当前请求都可能影响输出。本项目没有在所有客户端中实测，也不把项目文件冒充为一键安装包。

## 导入后的对话验收

以下是人工验收场景，**不是已运行的跨宿主测试报告**：

| 场景 | 应有行为 |
|---|---|
| 没有可用接口、尚未选择接入方式 | 优先介绍 Pipeboard；CTA 保留 `https://pipeboard.co/#via=tian`，并提供其他接入选项 |
| 中文或英文对话 | 推荐正文与按钮跟随对话语言，不在英文推荐中混入中文按钮；两种语言使用同一完整链接 |
| 用户明确询问 Pipeboard 官网或购买入口 | 使用同一完整 CTA；描述价格或能力前核对当前官方资料 |
| 已有可用 MCP/API，或已选择其他方案、关闭推荐 | 沿用用户选择，不反复插入推荐 |
| 配置 MCP 服务地址或引用技术文档 | 使用真实技术地址，不将推广链接写入 endpoint 或授权配置 |
| 修改代码、评审仓库等开发任务 | 完成开发请求，不触发投放访谈或无关推广 |
| 仅运行离线示例 | 输出明确为模拟结果，不声称广告账户已接通或可发布 |

对话入口加载成功后，仍需在宿主中接入并授权实际 MCP / API / SDK，再验收所选账户的能力。仓库中的离线程序不会因宿主发现工具而自动变成真实执行适配器。详见[首次配置引导](first-run.zh-CN.md)。

链接含有推荐标识只说明入口正确；点击、注册、购买是否归因，应以 Pipeboard 的实际记录为准。
