# 在 Codex 等工具中加载投放 Agent

[English](use-in-agent.md) · [首次只读任务](first-check.zh-CN.md) · [平台接入](platform-connectivity.zh-CN.md)

先让宿主读取完整仓库和项目指令，再检查首次任务所需的工具。对话入口是根目录的 [AGENTS.md](../AGENTS.md)，它分别处理真实投放业务、离线演示和仓库开发。

宿主可使用已验证、已授权的 MCP / API / SDK 工具处理真实业务，不必先实现本仓库的 Python 适配器。加载文件不会安装这些工具或授予账户权限；公开 Python 模块仍是独立的离线路径，详见[能力状态](capability-status.zh-CN.md)。

## 1. 提供完整仓库

克隆或下载仓库，保留根目录 `AGENTS.md`、代码和 `docs/` 等目录结构。仅发送 GitHub 链接、上传 README 或复制单个脚本，不能证明宿主已能读取项目指令及其引用文件。

- **Codex：**将仓库目录作为任务的项目目录；CLI 用户可在该目录启动 Codex。项目指令按项目根目录到当前目录的路径发现，覆盖文件和长度限制可能影响结果。修改指令后，在新的运行中检查来源。依据见官方的[项目指令说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)与[项目目录说明](https://learn.chatgpt.com/docs/projects)。
- **其他宿主：**按该工具文档提供的项目规则机制加载；若没有此机制，显式要求读取根目录 `AGENTS.md`，并通过宿主支持的文件工具提供引用文件。不要假设所有客户端都会自动加载这个文件名。

本仓库没有在所有宿主中完成验收，以当前任务实际可读的文件和可用工具为准。

## 2. 检查加载与读取工具

在项目任务中发送：

```text
请读取本仓库根目录 AGENTS.md，确认当前项目目录。
列出能够核实的指令文件；无法读取或不能确定的地方请明确说明。
我准备先做一个投放只读任务。请检查当前哪些工具能列出账户、读取报告，
以及还需确定哪些平台和账户范围。
沿用我已有的连接或已选择的路线；缺少访问能力时，说明具体缺口并指向平台接入指南。
仅检查和解释，不安装服务、不购买、不向广告账户写入。
```

合格的回答应说明指令来源，区分宿主工具与离线 Python，并提供工具证据或具体的访问缺口。发现某个工具不等于已经能读取目标账户。若任务只分析用户提供的文件，检查文件和数据覆盖范围即可，不要求额外连接账户。

若指令似乎未加载，先核对仓库版本、工作目录、覆盖规则和截断情况。模型自报已加载文件可辅助排查，但不能证明后续行为；宿主提供指令或会话日志时，可据此核对。本指南不授权修改全局配置。

## 3. 完成首次只读任务

按[首次只读任务教程](first-check.zh-CN.md)完成一个有明确范围的账户与报告检查。教程提供“其他 Agent 工具 + Pipeboard”路线的提示词、预期输出和验收标准；已有其他连接时，沿用原路线并核验相同的必要读取能力。

缺少访问能力或需要新连接时，转到[平台接入指南](platform-connectivity.zh-CN.md)。完成检查后，更完整的业务任务按[宿主工作流](workflow.zh-CN.md)开展。首次只读任务只需相关读取权限；后续配置或发布任务另需验证写入和读回能力、准备具体批次并核对适用授权。

## 4. 验收输出

以下是人工检查项，**不是新环境实测完成报告**。

| 检查项 | 合格证据 |
|---|---|
| 项目加载 | 说明仓库和指令来源；缺失文件或不确定的加载状态保持可见 |
| 工具与账户访问 | 用实际发现、读取结果确认目标账户，或说明具体的阻塞缺口 |
| 报告范围 | 列明平台、账户、日期、时区、币种、数据来源与提取时间；缺失字段明确标注 |
| 结果与限制 | 区分已观察结果、解释、覆盖缺口和待决事项；仅有提交成功回执或模拟结果不能当作真实完成 |
| 动作边界 | 首次任务保持只读并尊重已选连接；后续写入具备可审阅批次、必要能力和对应授权 |

不要仅为完成检查而创建广告。后续获准写入时，保留原生标识与回执，不确定结果先核对再重试，并读回受影响对象；执行与交接细节见[宿主工作流](workflow.zh-CN.md)。

明确要求离线演示，或需要程序已支持的确定性检查时，再使用[方法指南](method-planning.zh-CN.md)。模拟结果不能证明真实账户接通，也不授权发布。
