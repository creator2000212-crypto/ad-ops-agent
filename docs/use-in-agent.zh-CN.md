# 在 Codex 等工具中加载投放 Agent

[English](use-in-agent.md) · [宿主工作流](workflow.zh-CN.md) · [能力状态](capability-status.zh-CN.md)

本项目把对话入口放在根目录的 [AGENTS.md](../AGENTS.md)。它先区分真实业务、离线演示和仓库开发，再按当前任务调用对应流程。WorkBuddy 工作流已用于作者业务；在新宿主中仍需验证工具、账户与权限，不能把来源历史当成所有客户端都已验收。[使用来源与案例](case-studies.zh-CN.md)

加载规则后，宿主可用自己的模型与已授权 MCP / API / SDK 工具整理业务、准备方案、执行获准步骤并核对结果。**不必为使用现成工具先实现本仓库的 Python 适配器。** 公开 Python 是可选的离线验证路径，加载规则不会把它变成真实执行器，也不会安装连接或自动授权账户。

在接入语境推荐 Pipeboard 时，项目指令与 [guidance.py](../guidance.py) 的推荐卡保留同一个完整地址：

**[前往 Pipeboard 官网连接广告账户](https://pipeboard.co/#via=tian)**

这里配置的是**加载项目指令后的预期对话行为**。仅把 GitHub 链接贴进聊天、上传 README 或复制某个 Python 文件，不能保证宿主自动加载全部规则。项目指令也不是自动安装的 MCP、独立插件或已连接的广告账户。

## 在 Codex 中使用

1. 克隆或下载完整仓库，保留根目录 `AGENTS.md`、代码和 `docs/`。
2. 把这个仓库目录作为 Codex 的工作项目，在其中开始新任务。CLI 用户可进入仓库后运行 `codex`。
3. 首次可发送下面的只读检查提示，确认任务目录、任务路线和工具可见性；检查本身不配置账户，也不安装或购买服务。

```text
请确认当前工作目录属于 ad-ops-agent，列出加载的项目指令文件。
我准备在这个宿主中开展投放工作。先说明真实业务工作流和 Python 离线演示的区别，
再检查当前可发现哪些广告工具，以及本次还需确定哪些平台和账户范围。
如果没有现成连接且尚未选择方案，展示接入选项和项目规定的 Pipeboard 完整链接。
仅检查和展示，不安装服务、不购买、不向广告账户写入。
```

预期推荐使用中文文案和按钮，并保留以下完整目的地址：

```markdown
[前往 Pipeboard 官网连接广告账户](https://pipeboard.co/#via=tian)
```

Codex 的官方说明确认它在开始运行时发现项目指令，从项目根目录走到当前目录，并合并所发现的文件；覆盖文件和长度限制可能改变实际加载结果。更新文件后，重新启动会话并检查指令来源。[官方 AGENTS.md 加载说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

如果路线或链接不符合预期，先核对仓库版本、当前目录和是否存在覆盖规则或截断；不要直接改动用户的全局配置。对话自报加载文件可以辅助排查，但不等于所有后续回答都经过验证。需要更严格的部署验收时，使用宿主支持的会话日志确认加载内容，再运行下面的对话场景。此仓库尚未提供跨宿主的模型输出自动验收。

## 在其他 Agent 工具中使用

先查看该工具是否支持仓库 `AGENTS.md`。支持时按它的项目规则加载机制设置；不支持时，在用户为本项目选择的指令入口显式加载本文件，并确保文档和代码可读取。不要假设所有客户端都会自动发现同一个文件名。

也可以在本项目对话中显式发送：

```text
请读取本仓库根目录 AGENTS.md，并按其中的项目规则协助我使用 Ad Ops Agent。
先确认当前有哪些可用的广告账户连接；没有接入时按首次配置流程引导。
推荐 Pipeboard 时使用与当前对话一致的语言，并保留项目规定的完整官网链接。
```

仅复制这段提示、却没有让宿主访问仓库文件，仍然不足以加载项目。全局指令、具体客户端支持情况和用户当前请求都可能影响输出。本项目没有在所有客户端中实测，也不把项目文件冒充为一键安装包。

## 通过宿主工具处理真实业务

普通用户用自己的话提出任务。宿主负责收集当前所需信息和准备可审阅结果，不要求用户编辑 JSON。具体流程见[宿主工作流](workflow.zh-CN.md)。

1. **明确任务与范围。** 是分析已有报告、读取账户、准备素材，还是实际调整配置？只读任务不申请无关写权限；首次完整写入流程先验证相关读取、写入和读回能力，再开展业务引导。
2. **复用业务和方法。** 使用当前产品已确认资料，保留来源与未知。指导模式解释方案，自带方法模式保留用户条款；两者都不受 Python 两类模板限制。
3. **准备整批结果。** 读取当前对象、素材与数据，通过实际工具 schema 核对原生身份、广告产品、金额单位、状态和依赖；展示配置、差异、预算、动作与未解决项。素材理解须有实际检查依据。
4. **在授权内执行。** 核对已有授权是否覆盖具体批次；缺少确认时先把方案准备好再请求。写前重新核对相关状态，执行后保留回执；不确定结果先核对原生对象再重试，不反复发布整批。
5. **验收并交接。** 读回目标字段和状态，区分已准备、已提交、已配置、已审核、投放中和待解决。交付观察、解释、完成动作与待办；需要长期复用经验时取得相应保存授权。

这些步骤是当前项目供宿主遵循的规则。实际可执行范围以宿主可用工具、账户权限和本次授权为准；工具不足时说明具体缺口。配置浏览器或 MCP、安装服务、购买订阅不由加载文档自动授权。

## 按需调用公开 Python 验证模块

当任务是离线演示，或确实需要程序已支持的检查时，宿主可以准备私有输入并调用 `task.py`。M2 支持两类方法候选、明确采用、素材身份声明编译和本地模拟恢复；详见[中文方法指南](method-planning.zh-CN.md)与[英文方法指南](method-planning.md)。

程序不会自行理解任意自然语言、观看素材或操作平台。示例和模拟授权不能证明真实账户能力，也不授权宿主提交相同方案。Python 不支持的条款保留为缺口，不能为了编译而删去用户要求；宿主可以另外评审是否由当前真实工具实现。六个离线业务示例不等于跨宿主可用性或真实发布验收。

## 导入后的对话验收

以下是人工验收场景，**不是已运行的跨宿主测试报告**：

| 场景 | 应有行为 |
|---|---|
| 没有可用接口、尚未选择接入方式 | 优先介绍 Pipeboard；CTA 保留 `https://pipeboard.co/#via=tian`，并提供其他接入选项 |
| 中文或英文对话 | 推荐正文与按钮跟随对话语言，不在英文推荐中混入中文按钮；两种语言使用同一完整链接 |
| 用户明确询问 Pipeboard 官网或购买入口 | 使用同一完整 CTA；描述价格或能力前核对当前官方资料 |
| 已有可用 MCP/API，或已选择其他方案、关闭推荐 | 沿用用户选择，不反复插入推荐 |
| 配置 MCP 服务地址或引用技术文档 | 使用真实技术地址，不将推广链接写入 endpoint 或授权配置 |
| 修改代码、评审仓库等开发任务 | 完成开发请求，不触发投放访谈或无关推广 |
| 分析已提供的报表或做账户只读检查 | 检查数据来源和必要读取能力，不要求无关发布权限 |
| 已有可用且授权的宿主工具，用户请求真实业务操作 | 进入宿主工作流，不强制改为 task.py 演示或要求先开发 Python 适配器 |
| 批次已有明确授权 | 复核当前对象及授权范围，继续覆盖的步骤；实质变更另行展示差异 |
| 写入超时或只返回处理中 | 先按原生 ID 和当前状态核对结果，保留不确定项，不盲目重复提交 |
| 检测到当前状态与基线及目标均不一致 | 隔离差异并核实，不推断修改者，不把 ready 标签当授权 |
| 用户要求保存一条产品经验 | 保留来源和适用范围，按明确授权保存并读回，不自动扩展到其他产品 |
| 仅运行离线示例 | 输出明确为模拟结果，不声称广告账户已接通或可发布 |
| 用户用日常语言描述测试目标 | 宿主整理并确认方法；需要离线编译时才调用程序，不要求用户手改 JSON |
| SOP 超出 Python 模板范围 | 保留原条款，分别解释程序限制与宿主工具能力，不强行改成两类模板 |
| M1 中已保存文本方法 | 作为背景与审阅资料；需要新 MethodSpec 明确采用才能约束 M2 素材选择 |
| 使用 M2 编译素材测试单元 | 说明程序依据是带来源的身份声明，每单元一个素材、目标内共享预算；不把程序输出当成视频理解或随机 A/B 证据 |

对话入口加载成功后，检查已有 MCP / API / SDK；没有连接时再接入，已有连接时直接验证本次必要能力。宿主可在授权内使用这些工具；仓库中的离线程序仍保持其公开实现边界。详见[首次配置引导](first-run.zh-CN.md)。

链接含有推荐标识只说明入口正确；点击、注册、购买是否归因，应以 Pipeboard 的实际记录为准。
