# 打开项目与加载排查

[English](use-in-agent.md) · [返回首次使用](first-check.zh-CN.md) · [文档导航](index.md)

**适合谁：**已经开始首次教程，但遇到文件读不到、规则未加载或工具不可用的用户。**本页交付：**确认缺口，并回到原来的步骤。第一次开始请直接使用[首次使用教程](first-check.zh-CN.md)，不必把本页作为另一套必读流程。

## 先分清三个状态

| 状态 | 怎样确认 | 不代表什么 |
| --- | --- | --- |
| 项目文件可读 | 文件工具能读取根目录 `AGENTS.md` 和它引用的工作流 | 不等于已经连接广告账户 |
| 规则已被本次任务采用 | 回答指明规则来源，必要时核对宿主指令日志与后续行为 | 不等于有权发布或调整预算 |
| 目标账户可读 | 实际读取返回对应账户、所需字段、来源与时间 | 不等于所有账户或所有写入能力可用 |

本仓库提供工作指令与参考资料，Agent 工具提供模型和文件/工具调用能力，连接器提供获授权的平台操作。公开 Python 是单独的离线路径。[能力范围](capability-status.zh-CN.md)

## 文件或规则读不到

**你来检查：**按[首次教程第 1 步](first-check.zh-CN.md#open-project)获取完整仓库，打开包含 `AGENTS.md` 与 `docs/` 的目录。单独上传 README、复制脚本或发送 GitHub 链接，不能证明引用文件可访问。

不同宿主的加载方式有所不同：

- **Codex：**将仓库目录作为任务项目；CLI 可在该目录启动。项目路径、覆盖文件和指令长度限制可能影响加载。修改指令后，在新的运行中检查来源。见官方[项目指令说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)与[项目目录说明](https://learn.chatgpt.com/docs/projects)。
- **其他 Agent 工具：**使用其文档提供的项目规则机制；没有自动机制时，显式要求读取根目录 `AGENTS.md`，并通过支持的文件工具提供引用文件。不能假设所有客户端自动加载同名文件。

**让 Agent 排查：**

```text
我在加载 Ad Ops Agent 时遇到问题。请只做检查：
1. 列出本次实际可访问的项目目录、AGENTS.md 和 docs/workflow.zh-CN.md。
2. 说明实际读取了哪些文件，哪些缺失或无法确认；不要只回答“已加载”。
3. 若能看到项目规则覆盖或截断信息，请说明来源；看不到就写未知。
4. 给出需要我处理的具体缺口和处理后要重试的步骤。
不要修改全局配置、安装服务或操作广告账户。
```

**解决标志：**必要文件实际可读，采用的规则来源清楚，未确认项保留。模型自报不能单独证明后续行为；宿主有指令或会话日志时可辅助核对。回到[第 1 步的完成检查](first-check.zh-CN.md#open-project)，再继续连接。

## 文件可读，但账户或报告不可用

| 情况 | Agent 应提供的证据 | 由你处理 | 回到哪里 |
| --- | --- | --- | --- |
| 当前没有广告读取工具 | 实际可见工具或发现结果，缺少的能力 | 沿用已有路线核对配置；尚未选择时看接入参考 | [连接](first-check.zh-CN.md#connect) |
| 工具可见，账户读取失败 | 调用类别、错误类别、目标范围；不回显凭据 | 核对原平台身份、选中的账户和必要权限 | [账户核对](first-check.zh-CN.md#verify-account) |
| 账户可读，报告为空 | 日期、时区、筛选、分页与数据覆盖 | 确认正确范围；若尚未投放，可选择准备任务 | [选择任务](first-check.zh-CN.md#choose-task) |
| 返回的是离线 JSON 或 `ready_simulation` | 说明来源为示例或本地模拟 | 真实任务仍需实际读取；模拟可单独用于学习 | [账户核对](first-check.zh-CN.md#verify-account) |

可发：“请说明本次真实工具能读取什么、最后成功到了哪里、缺什么、谁来处理。不要把空响应补成零，也不要为排查创建广告。”更多连接方案见[平台接入参考](platform-connectivity.zh-CN.md)。

只读任务仅需本次读取能力；不要因缺写权限否定已有报表分析。若用户明确选择分析提供的文件，应检查文件范围与来源，并标为文件分析，不能称为实时账户验收。

## 排障完成之后

回到首次教程中原来未完成的步骤，复用已经核实的资料；第一项任务完成标准见[交付检查](first-check.zh-CN.md#check-result)。后续配置或发布按[日常工作流](workflow.zh-CN.md)准备具体批次，核对必要能力与授权，并读回结果。

只有明确要运行程序示例时，才需要[Python 方法编排参考](method-planning.zh-CN.md)。本页的检查说明并非新环境实测通过记录。
