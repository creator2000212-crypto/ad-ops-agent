# 首页与案例展示规范

首页回答四个问题：这是什么、实际交付过什么、为什么能复用、怎样开始。长过程放在案例和方法文档，不靠一张图承载全部说明。

## 阅读顺序

1. 品牌横幅：项目名、人与 Agent 的分工、真实业务来源。
2. 两张成果图：先呈现交付或状态，再链接到完整案例及证据范围。
3. 通用工作流：理解业务 → 准备方案 → 整批确认 → 授权执行 → 结果核对 → 复盘迭代。
4. 三个起点：已有连接、尚未接入、不接账户运行公开示例。
5. 文档导航：按读者的问题分组，保留可搜索的 Markdown。

## 文字与证据

- 案例数字必须说明单位和阶段。Meta 的 20 是建单候选与逐条文案，不是发布量；TikTok 的可投是历史回执状态，不是消耗或效果。
- 区分历史业务、宿主工具中的实际操作、公开 Python 的离线演示。图片是脱敏整理图，不是 Agent 界面截图。
- 每张成果图在相邻正文中说明人的决策、当前证据范围和未完成项，并链接案例页。
- 使用者可以更换产品、方法和连接工具；不要把某次业务方法写成项目的固定策略。
- 图片须有完整替代文字。关键数字、状态和风险边界也要留在正文，避免只存在图片里。

## 图片与排版

- 横幅、Meta、TikTok、工作流四类图片各有中英、浅色/深色、宽屏/窄屏版本，位于 [`assets/showcase/`](assets/showcase/)。
- README 使用 `<picture>` 的 `media` 条件选择主题与窄屏图，并保留 `<img>` 的浅色宽屏回退。只放图片选择标记，不放预览 HTML 的脚本、主题按钮或 CSS。
- 首页优先使用一张品牌图、两张成果图和一张流程图。案例页可展开方法和对象状态；新增案例先检查首页是否需要替换已有摘要，而非一律追加图片。
- 浅底、深色正文和绿色强调色为默认视觉；暗色版使用相同信息层级。手机端重排内容，不把宽图简单缩小。
- 展示用 PNG 来自 2026-09-25 提供的本地视觉预览；同目录已补入单独提供的 32 份可编辑 SVG 源文件。修改图中文字或版式时，以对应 SVG 为编辑起点，重新导出并检查中英、明暗、宽窄屏的 PNG。
- 分享预览使用独立的 [`social-preview.svg`](assets/showcase/social-preview.svg) 与 [`social-preview.png`](assets/showcase/social-preview.png)，不替代 README 横幅。PNG 为 1280 × 640、小于 1 MB；GitHub 仓库 Social preview 需在仓库设置中单独上传并检查显示。

## 更新检查

[`assets/showcase/content.json`](assets/showcase/content.json) 集中记录公开展示的事实与文字：`facts` 保存 Meta 数量、日期，以及 TikTok 日期、逐项状态；中英文模板保留不同宽度的表达与证据边界，明暗主题共用一组文字。它是经人工审阅的内容基准，不是新的历史证据。

维护顺序：

1. 先核对事实来源与证据范围，再修改 `facts` 或相应中英文模板。不得为了通过检查删除未知项、待办或“准备不等于发布”“可投不等于消耗或效果”等边界。
2. 同步对应 SVG 和两份 README 的案例正文、日期说明、替代文字。文案重写也要显式更新模板，不使用自动接受当前文件的快照更新流程。
3. 运行 `python3 scripts/showcase_content.py`、`python3 scripts/check_repository.py`，以及 `python3 -m unittest discover -s tests -p 'test_showcase_content.py' -v`。
4. 重新导出受影响的 PNG，目视核对中英文、明暗、宽窄版本的文字、截断、留白和可读性。现有 PNG 与 SVG 分别提供，尚无可复现的 PNG 导出流水线，也不宣称二者像素一致。
5. 合并前在 GitHub 实际预览中再核对 `<picture>` 选择和 Markdown 排版。

自动内容检查逐项比较 32 个 SVG 的 `<text>` 序列，并定点比较两份 README 的 Meta/TikTok 案例段、紧随其后的日期与证据段、四张图的 alt 和 `<picture>` 图片选择关系。单处数字、状态、日期或语言变动都会要求审阅；不把其他正文中的任意数字当作案例事实。空白变化不影响结果，缺失或无效 manifest 会报错。

自动文本检查覆盖 SVG 与 Markdown，不读取 PNG 图中文字，也不验证 SVG 的渲染、布局或无障碍描述。PNG 仅检查文件齐全、签名和尺寸范围，仍需重新导出与目视检查；独立分享预览及其他文档不在这份文字契约范围内。历史结论是否成立、中英文语义是否准确仍由维护者结合来源审阅。
