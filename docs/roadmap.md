# 路线图与验收标准

项目正在把已经通过 Agent 工具用于实际业务的工作流整理成他人可复用、可验收的开源 Agent。真实工作历史是产品来源，公开 Python 的离线测试是代码证据；新宿主、连接器和广告产品仍需各自验证。路线图不承诺发布日期，也不把任一类证据替代成另一类。

接下来两条路线并行推进：**宿主工作流复用与证据完善**，以及**Python 独立平台适配器工程**。已经具备授权工具的宿主，可以先开展当前任务，不必等待 Python 原生执行器完成。

## 已有基线

| 层次 | 当前基础 | 仍需明确的边界 |
|---|---|---|
| Agent 工具中的业务实践 | 素材审计、Meta/TikTok 批次与配置记录、报表/归属核对、异常处理、巡检和操作复盘 | 不同记录分别证明准备、提交或读回；并非全部闭环成功，也没有据此证明 Google 的真实部署 |
| 公开宿主说明 | 按任务组织输入、整批审阅、授权执行、逐对象核对和私有记录；提供任务模板 | 正确加载指令、当前工具和账户权限、各环境可用性由部署者验收 |
| Python 验证程序 | 结构化检查、有限方法编排、知识/私有记录、离线巡检、模拟执行与恢复 | 不调用大模型或平台，拒绝 live 模式；不能承担真实身份、批准与发布 |

历史来源见[脱敏案例](case-studies.zh-CN.md)，具体边界见[能力范围](capability-status.zh-CN.md)。公开化工作提炼通用机制，不复制作者的客户数据、固定预算、阈值或默认打法。

## 路线 A：让宿主工作流更容易复用与验收

### A1 · 从六类实际任务开始，而不是重做一遍所有初始化

**目标：**用户说出要做的事，Agent 能沿正确入口完成准备与交接。六类入口是素材与测试准备、批次搭建/调整、日报/归属核对、巡检/操作复盘、配置/追踪排障、迁移/结构清理。

当前[宿主工作流](workflow.zh-CN.md)与[任务记录模板](../templates/task-record.zh-CN.md)提供公共步骤。后续在新手与熟手的实际使用中检查：先核对本次连接能力，再复用业务背景与方法；仅补影响当前任务的信息。新手得到可选择的具体方案，熟手的方法和不修改范围被保留，超出 Python 两类模板的条款不会被静默删除。

**验收：**日报不强迫完成发布访谈，未知长期收入不阻塞无关分析，已有资料不反复问；用户的中途纠正能改变本轮结果；整批差异能直接审阅，缺项和待办清楚可见。记录必要的交流与纠正证据，不能用结构化测试冒充真人使用验收。

### A2 · 为已有工具建立可复查的能力与结果记录

**目标：**把“这个环境能做什么、这次究竟做到了哪”说明白。

按平台、账户、广告产品和任务，记录实际使用的 MCP/API/SDK 或获准后台操作能力。明确字段单位、原生对象与包装 ID、分页和覆盖、权限缺口、错误与异步状态。媒体工具记录查看范围；只有文件名或制作说明时，不把推断写成内容核验。

回执由对应操作后的读取结果生成，保留预期值、实际值、对象、来源和检查时间。历史材料中出现过硬编码 `ACTIVE` 与已保存快照不一致的情形；新工作流必须能暴露此类证据冲突，不把旧报告的成功文字继承为当前事实。本次公开化不等于已经修复所有私有历史脚本。

**验收：**工具返回成功但最终字段不符、提交后待审、父级暂停、读取失败和已观察到投放分别报告；结果未知先查询，不盲目重放。只读任务只验收读取和交付，不为补齐流程制造一次写入。

### A3 · 在另一个明确环境复验完整小任务

**目标：**验证其他使用者能否用自己的产品、方法与工具完成一轮工作。

先完成一项读取或准备任务，再在已有或新取得的明确授权内验证所需外部变更。覆盖已有方法、缺权限、部分成功、中断、当前配置漂移和后续回验。保留产品选择、确认范围与实际操作证据；一个环境的成功不外推为跨宿主保证。

**验收：**在声明的宿主、工具版本、账户与广告产品范围内，方案可审阅，获准步骤完成，逐对象结果可读取，未完成项可接续。新增账户、费用或方法变化能够返回具体差异；不要求每个已获准机械步骤再次确认。公开脱敏的覆盖与失败模式，私有对象和业务数据留在部署者环境。

### A4 · 完善私有成长与可比结果交接

**目标：**让经验减少未来劳动，同时保留人的方法选择与证据边界。

用户纠正先修本轮结论，明确要求长期保存后，再写成有来源、产品范围和版本的私有约定。区分用户采用、实际执行和效果证据，保存反例、适用条件和撤回原因。报告继续保留时间、覆盖、归因、数据源、事件成熟度与可比性，下一轮先回验相关待办。

**验收：**上次建议未执行时不评价其执行效果，一次相关性不晋升为普适策略；公共知识更新不覆盖用户方法，用户撤回的方法不继续影响后续任务。定时执行仅在用户要求并验证调度后启用，不能从文档或“已启用”文字推断持续运行。

## 路线 B：Python 独立平台适配器工程

这条路线使公开程序未来能够自行读取和操作平台。它不替代宿主现有工具路线；当前离线限制在相应工程验收完成前保持不变。

### 已实现的离线基础

- 结构化业务档案、模拟连接快照、四类 readiness、有限引导与按字段记录的提问进度。
- 素材元数据筛选、逻辑草稿、预算范围检查、计划与档案 hash、模拟授权和执行前复核。
- SQLite 模拟对象、读回、故障注入和同一 state 内的续跑核对。
- 版本化知识检索、结构化观察驱动的建议、证据缺口和来源复核提示。
- M1 私有库：workspace/产品逻辑隔离、版本/CAS、事件幂等、候选/采用/撤回、历史和条件复用；冲突不覆盖，相关采用条目变更使旧计划失效。
- M2 有限方法闭环：两类候选、明确采用、逐行中英文 SOP 标签、带来源的组件身份与单素材测试单元；`task.py` 串联私有任务副本、独立计划和模拟恢复。
- 离线巡检：输入快照诊断、差异判断、计划登记、本地台账与另行提供的后置快照比较（demo 为预设快照）；`ready` 不等于授权，`apply` 无平台写入。
- 拒绝 live、非 `generic_draft` 及执行契约未实现的字段；档案额外保存字段不自动获得执行语义。

`scripts/demo_methods.py` 覆盖 App/电商/线索 × 两种方法路线的六个虚构输入，检查中断、恢复、重复运行与方法修订后旧计划失效。[巡检 demo](../demo/README.zh-CN.md)展示另一套离线数据链。它们验证代码与持久化，不是六类客户部署，也不是自然语言访谈、实盘发布或经营效果验收。

### B1 · 一种真实只读来源与素材导入

**目标：**让 Python 从真实来源获得当前信息，减少重复填写。

实现一个可替换连接绑定，限定账户范围，读取时区/币种、对象配置、身份、事件和媒体引用。导入素材时保留原件身份、技术规格、来源和派生关系。

**验收：**来源与时间可追溯，缺权限、缺数据和真实零不同，分页与覆盖可核对，换入口仍识别同一原生对象，且未调用写接口。此阶段不自动具备素材语义理解或确认权限。

### B2 · 一个明确广告产品的原生批次执行

**目标：**由 Python 在一个已核验范围内完成准备、确认、执行和读回。

实现原生字段编译、媒体上传与异步处理、身份/帖子引用、预算/排期及真实确认机制。按实际业务选择产品分支，不能为了展示三平台而静默换成别的广告产品。

**验收：**审阅与执行内容一致；重复运行、超时和部分失败先核对；重叠预算明确；实际配置与有效状态逐对象读取。认证、批准者身份、撤销/到期、并发和跨运行防重独立验收，不把模拟授权文件变成生产凭据。

### B3 · 对象谱系、恢复与结果数据

**目标：**让程序处理媒体故障、状态变化、并发修改和数据回补。

接入选定[操作卡](operations.md)的原生实现，建立文件、变体、媒体、creative、ad、post 关联与生效时间。加入 as-of 快照、归因、事件成熟度和实际素材暴露量；恢复动作保留审核依据与停止条件。

**验收：**换素材后可分段追溯；互动保留有真实帖子证据；未知学习状态不被补成确定结论；过审不宣称恢复原表现；失败与不可比样本保留。方法和经验不自动获得调用平台工具的权限。

### B4 · 扩展广告产品、平台与按需协作

按需求增加 TikTok 标准/Smart+/Spark、Google Search/Demand Gen/PMax 等分支，以及用户授权的调度或协作能力。每个分支单独声明可读取、创建、修改、预览和报告的范围。

**验收：**不支持时有具体原因，不把不同平台指标假装等价，共享预算与币种正确处理，换连接器不丢既有对象身份和回执。每增加一项公开能力，都补相符的集成证据；不为了路线图先建多租户 SaaS。

## 贡献工作如何切小

| 可独立贡献的单元 | 应交付的证据 |
|---|---|
| 一类宿主任务的复用说明 | 最小输入、任务步骤、用户决定、实际交付、缺口与环境范围 |
| 一种工具能力映射 | 当前 schema、字段单位、对象身份、缺省/空值/分页行为与验证范围 |
| 一项回执或异常恢复检查 | 计划与读回对应关系、未知结果查询、部分失败和重试边界 |
| 一个 Python endpoint 或媒体能力 | 官方来源与版本、脱敏响应样例、边界用例及限定范围的集成证据 |
| 一个业务引导或私有经验分支 | 哪项任务依赖它、允许未知的条件、纠正/撤回与计划失效用例 |
| 一种报告映射 | 事件定义、时区/窗口、归因、成熟度、缺失语义和覆盖核对 |

公开示例使用虚构标识和数据，凭据与真实账户内容不进入仓库。能力说明随实现同步，分别标记历史使用记录、宿主环境验收、离线测试和原生适配器集成。

## 设计契约不是已运行测试

[acceptance-scenarios.json](../contracts/acceptance-scenarios.json) 是接入与恢复验收设计；[connector-contract.json](../contracts/connector-contract.json)、[creative-recovery.json](../contracts/creative-recovery.json) 是接口/工作流设计；[experience-catalog.json](../contracts/experience-catalog.json) 和 [onboarding-extensions.json](../contracts/onboarding-extensions.json) 是候选知识与字段扩展。文件存在不代表运行时已加载，也不代表验收已经完成。

优先交付能减少重复填写、配置错误和重复执行的小闭环。经营策略、成本阈值与创意方向保持可选；自动预算优化和覆盖所有行业不是两条路线开始工作的前提。
