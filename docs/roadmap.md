# 路线图与验收标准

项目从可复验的离线契约开始，再逐步加入真实接入、业务理解和广告产品。此路线图描述交付条件，不承诺发布日期；官方 SDK 示例、设计契约和模拟结果都不能代替账户联调。

## 已有基线：离线运行时

当前可运行的部分包括：

- 结构化业务档案、模拟连接快照和四类 readiness 评估。
- 最多三个相关新问题与按字段记录的提问进度。
- 素材元数据筛选、逻辑草稿、批次预览、预算范围检查。
- 计划与档案内容 hash 绑定、模拟授权与执行前复核。
- SQLite 模拟对象、读回、故障注入和同一 state 续跑核对。
- 版本化投放知识检索，接入初始化和方案评审；结构化观察驱动的诊断建议、证据缺口和来源复核提示。
- 拒绝 live 模式、非 `generic_draft` 广告产品，以及执行简报、目标、预算和素材筛选契约中未实现的字段；业务档案中额外保存的字段不自动获得运行语义。

运行与测试命令见 [根 README](../README.md)。本地测试验证的是输入、范围、一致性与恢复逻辑；不是平台认证、真实广告发布或经营效果测试。详细能力边界见 [架构](architecture.md)。

## 阶段 1：一种真实只读来源与素材导入

**目标：**减少用户重新填写字段的劳动，让初始化从可靠的现状摘要开始。

实现一种可替换 API/MCP 连接绑定，限定账户范围；读取账户、时区/币种、现有配置、身份、事件和媒体引用。素材导入提取原文件身份、技术规格、可用来源与派生关系。一个平台可用时先服务该平台，不要求三平台全接通。

**验收：**来源和提取时间可追溯；权限缺失、空数据和真实零不同；分页与覆盖完整；换入口仍识别同一原生对象；未调用写接口。对照人工填写基线，记录减少的输入和仍需纠正的字段。

## 阶段 2：渐进对话与上下文复用

**目标：**用户不必先编写完整 JSON，Agent 能理解产品、市场、路径、变现、方法和当前问题。

加入自然语言候选提取、已知摘要、分支问题、理解确认和作用域管理；保留来源、未知与冲突。把目标设计中的偏好/方法类型与当前 facts 状态模型明确衔接，不把模型推断直接记为已确认事实。

**验收：**可从可靠资料回答的字段不重复问；未知 LTV 不阻塞无关工作；Web/App/IAA/IAP/混合分支正确；用户改方法时只更新适用范围；聊天确认不触发广告写入。readiness 按实际任务解释缺口，而非一个总体完成分数。[业务初始化](onboarding.md)

## 阶段 3：首个明确广告产品的真实批次闭环

**目标：**在一个已核验平台、账户和广告产品范围中完成准备→确认→执行→读回。

实现原生参数编译、可用能力预检、媒体上传/处理、身份和帖子引用、版位预览、预算/排期以及真实用户确认。先选择实际业务需要的广告产品，不为展示“支持三平台”而静默替换用户需求。

**验收：**整批预览与执行计划一致；确认范围内步骤连续完成；重复运行/网络超时先核对而不重复创建；新旧投放重叠预算明确；实际字段与状态逐对象读回。真实认证、确认、回执与并发控制必须独立验收，不复用模拟授权文件作为生产凭据。

## 阶段 4：身份谱系、条件恢复与结果交接

**目标：**处理媒体故障、误拒疑点、人工并发修改和短期数据不完整，让投放人员得到可判断的结果。

实现文件→变体→媒体→creative→ad→post 关联及生效时间，接入 [16 张操作卡](operations.md) 的选定流程。按照项目方法支持有边界的重传、创意重建或关联修复，并分开记录审核、交付与效果。结果层引入时区、归因、as-of 快照、事件成熟度和真实素材暴露量。

**验收：**同一 ad 换素材后能分段追溯；互动是否保持有真实帖子证据；学习状态 unknown 不被自动补齐；恢复失败样本保留；过审不宣称恢复原表现；没有可比较证据时只展示观察与假设。[Meta 素材恢复](meta-creative-recovery.md)

## 阶段 5：扩展广告产品、平台与协作

**目标：**在同一公共底座上增加明确的产品分支，而不是复制三份不同的执行系统。

逐步增加 TikTok 标准/Smart+/Spark、Google Search/Demand Gen/PMax 等实际需要的分支；每个分支声明可创建/修改/预览/报告的能力和限制。按需求扩展素材语义理解、收入来源、多成员协作及用户授权的调度。

**验收：**不支持的广告产品返回具体原因；不同平台指标不假装等价；共享预算与多币种正确处理；连接器更换不丢对象身份和既有回执。每增加一项能力，都有与公开声明匹配的集成证据。

## 贡献工作如何切小

| 可独立贡献的单元 | 应交付的证据 |
|---|---|
| 一个 endpoint 的字段/状态映射 | 官方来源与版本、脱敏响应样例、缺省/空值/分页行为、边界用例 |
| 一种媒体规格或就绪检查 | 明确广告产品、输入/输出、异步失败与超时分支 |
| 一张操作卡的实现 | 触发、条件、动作、对象影响、可观察成功与停止条件 |
| 一个 onboarding 分支 | 哪项任务依赖它、允许的未知、有限问题与变更失效用例 |
| 一种真实报告映射 | 事件定义、时区/窗口、归因、成熟度和缺失语义 |

公开示例使用虚构标识和数据，凭据与真实账户内容不进入仓库。能力说明要随实现同步，区分“定义了契约”“通过离线测试”和“在限定环境完成联调”。

## 设计契约不是已运行测试

[acceptance-scenarios.json](../contracts/acceptance-scenarios.json) 是未来接入与恢复的验收场景；[connector-contract.json](../contracts/connector-contract.json)、[creative-recovery.json](../contracts/creative-recovery.json) 是接口/工作流设计；[experience-catalog.json](../contracts/experience-catalog.json) 和 [onboarding-extensions.json](../contracts/onboarding-extensions.json) 是候选知识与字段扩展。它们不会因为存在于仓库就自动启用。

优先交付能减少重复填写、配置错误和重复执行的完整小闭环。经营策略、成本阈值和创意方向保持可选；自动预算优化或覆盖所有行业不作为完成这些阶段的前提。
