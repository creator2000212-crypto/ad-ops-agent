# 第一次使用：拿到第一份结果

[English](first-check.md) · [项目首页](../README.zh-CN.md) · [文档导航](index.md)

**适合谁：**第一次使用本项目的产品负责人或投手。**完成后：**拿到一份投放准备清单、账户检查报告，或已有方法的核对单。你通过对话提供信息，无需编写代码或填写 JSON。

按这条顺序开始：**打开项目 → 核对连接与账户 → 说明本次需求 → 选择一项任务 → 核对结果。** 已完成且仍适用于本次任务的步骤可以跳过。

本页以 **Agent 工具 + Pipeboard + 一个 Meta（Facebook / Instagram）账户**说明接入。已有其他连接可以继续使用，核对相同的必要读取能力；TikTok / Google 接入见[平台接入参考](platform-connectivity.zh-CN.md)。本页第一项任务都只读取和准备，不创建广告、不改预算、不启停对象。后续发布另需必要能力、具体方案与相应授权。

> 验证状态：接入资料已于 2026-09-25 核对；尚无按本页从新环境开始的完整实测或独立用户通过记录。[查看验证范围](#validation)。

## 开始前，只需准备这些

- 一款能读取项目文件、使用相应广告连接工具的 Agent 工具，以及一个有权访问的广告账户。尚无连接可在第 2 步选择。
- 已有产品介绍、落地页、素材或 SOP（现有工作方法）就带上；缺少的内容由 Agent 根据本次任务追问。
- 暂时只想了解成果、不连接账户：先看[课程业务例子](build-from-zero.zh-CN.md)或[离线示例说明](../demo/README.zh-CN.md)，无需安装 Python。

<details>
<summary><strong>这些词是什么意思？</strong></summary>

| 文中用词 | 你现在需要知道的意思 |
| --- | --- |
| Agent 工具 / 宿主 | 你与 AI 对话、让它读取文件和调用工具的软件 |
| 这个项目 | 一组工作规则、流程和参考资料；在 Agent 工具中打开后使用 |
| MCP / 连接器 | 让 Agent 使用外部广告工具的连接方式；API / SDK 是其他技术接入方式 |
| `AGENTS.md` | 本项目给 Agent 的工作指令文件；打开文件夹并不自动证明规则已加载 |
| 只读 | 查看数据和配置，不修改账户 |
| 读回核对 | 操作后重新读取对象，检查结果是否符合方案；后续写入任务会用到 |

</details>

## 1. 下载并打开项目

**你来做：**打开[仓库首页](https://github.com/creator2000212-crypto/ad-ops-agent)，点击 **Code → Download ZIP**，解压下载文件。在 Agent 工具中选择打开解压后的项目文件夹；文件夹通常名为 `ad-ops-agent-main`。具体菜单按所用客户端操作。[GitHub 下载说明](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-source-code-archives)

打开的是包含下面文件的那一层，而不是它外面的下载目录，也不是单独的 Markdown 文件：

```text
ad-ops-agent-main/
├── AGENTS.md
├── README.zh-CN.md
└── docs/
```

**让 Agent 检查：**在该项目的对话中发送：

```text
请读取当前项目根目录的 AGENTS.md 和 docs/workflow.zh-CN.md。
说明你实际读到的规则文件；读不到时告诉我缺少哪个文件或访问能力。
后续沿用已知信息，只问影响本次任务的缺项。此时先不操作广告账户。
```

**完成标志：**文件工具能读取这些文件，回答指出采用的规则及无法确认的加载项。宿主有指令加载日志时也可核对。若读不到，查看[打开项目与加载排查](use-in-agent.zh-CN.md)，解决后回到本步骤。仅粘贴 GitHub 链接不能保证加载完整项目。

<details>
<summary>熟悉 Git 的用户也可以克隆</summary>

```bash
git clone https://github.com/creator2000212-crypto/ad-ops-agent.git
cd ad-ops-agent
```

随后在 Agent 工具中打开该目录。ZIP 是下载时的版本快照；后续更新需重新下载或通过 Git 更新，自己的业务资料放在仓库外的私有目录。

</details>

<a id="connect"></a>

## 2. 准备账户连接

**已有可用连接：**直接进入第 3 步核对本次账户，无需重复购买或重配。**尚未选择连接：**建议先了解 Pipeboard，减少自行维护连接的工作；可[前往 Pipeboard 官网连接广告账户](https://pipeboard.co/#via=tian)。套餐和账户权限以当前服务为准，其他路线见[接入参考](platform-connectivity.zh-CN.md)。

**你来做：**在 Pipeboard 的 Connections 页面连接 Meta，选定允许访问的账户；随后在 Agent 工具支持的远程 MCP 配置中填写：

| 配置项 | 填写或处理方式 |
| --- | --- |
| 连接名称 | 自己便于识别的名称，例如 `Pipeboard Ads` |
| 连接类型 | Streamable HTTP（远程 MCP 的传输方式） |
| 服务地址 | `https://ads.mcp.pipeboard.co/` |
| 登录 / 授权 | 支持相应 OAuth 流程的客户端按授权页面完成；其他方式依照官方指引放入客户端安全配置 |

以上字段依据[Pipeboard 官方接入指南](https://pipeboard.co/guides/ads-mcp)。菜单名称因客户端而异；找不到配置入口时，先确认客户端是否支持该连接方式。已有 Meta 专用连接可继续使用，不必重配。

为本次任务优先选择可用的只读凭据或工具限制，具体可用范围见[权限说明](https://pipeboard.co/guides/api-token-permissions)。聊天要求“只读”不等于服务端权限受限；密钥和 token 不放入对话或仓库。

**完成标志：**客户端能发现账户、对象和报告的读取工具。下一步还要用实际读取核对账户；连接成功提示本身不够。

<a id="verify-account"></a>

## 3. 核对一个账户

发送下面的请求，然后从实际返回的列表中选择本次账户：

```text
检查当前广告连接，只使用读取能力。
列出当前获授权的 Meta 账户供我选择，不读取其他账户的表现数据。
如果我已指定账户，按原生账户 ID 核对。
读取所选账户的名称、时区、币种，注明来源和读取时间；缺项明确列出。
不要安装服务、扩大授权、创建对象或修改账户。
```

**Agent 应交付：**本次选定的平台与账户、读取到的基本信息、来源、时间及缺口。账户原生 ID 用于私有会话中的核对，对外展示时脱敏。

**完成标志：**目标账户真实可读；必要字段若不可读，说明影响并补齐依赖它的任务前提。示例 JSON、`ready_simulation` 或模型声称“已接通”均不算真实读取。缺少访问能力时先按[排障表](#troubleshooting)处理，保留已提供信息。

<a id="choose-task"></a>

## 4. 说明需求，只选择一项任务

连接核对后，Agent 先沿用已知资料，最多补问三个问题：**目前是否有广告在投？本次最想完成什么？有现成方法还是希望获得引导？** 经验只决定解释深度，不授予操作权限。所需业务背景见[业务与合作方式](first-run.zh-CN.md)，无需先读完它或填写整份问卷。

| 你现在的情况 | 第一项任务 | 你会拿到什么 |
| --- | --- | --- |
| 有产品，尚未投放 | A：整理投放准备 | 业务摘要、缺项、素材准备清单和候选测试方向 |
| 已在投放，想了解现状 | B：检查一个完整投放日 | 有来源的报告、观察、数据问题与下一步 |
| 已有 SOP，想提高效率 | C：核对并沿用方法 | 原方法条款、支持情况、缺失条件与待确认方案 |

<details>
<summary><strong>A · 有产品，尚未投放：复制这条任务</strong></summary>

```text
账户已核对。我有产品，但尚未开始投放，希望你引导我准备第一轮测试。
请先读取我提供的产品介绍、落地页和现有素材；无法读取的内容明确列出。
了解目标国家、Web 还是 App、转化流程、什么算有效结果，以及我能接受的预算边界。
复用已提供的信息，只问影响本次准备的缺项；没有的资料不要代填。
先给业务摘要、素材准备清单和带适用条件的测试方向，预算和方法由我确认。
本次只准备，不创建或发布广告。
```

**完成标志：**用户能修正业务摘要，知道缺什么、谁来补、准备好了之后审阅什么。没有历史数据可明确记录为尚无历史，不能虚构效果或预测保证。

</details>

<details>
<summary><strong>B · 已在投放：复制这条检查任务</strong></summary>

```text
对刚才选定的一个 Meta 账户，检查按账户时区刚结束的自然日，不跳过无消耗日。
写明具体日期、时区、币种、统计层级、目标事件、归因口径和数据截至时间。
读取账户及广告组表现，核对分页和覆盖范围；缺失数据不要补零。
复用已有业务资料、已确认方法和上轮待办，只问影响判断的缺项。
未确认目标成本或方法时先报告事实，不自行设停投或加预算阈值。
把平台归因结果与后端有效线索、收入分开，注明归因回补及结果成熟度的限制。
如需读取对象当前状态，单列读取时点，不混作当日效果状态。
交付范围与完整性、主要观察、建议及依据、待确认项、来源和下一步。
本次只分析，不修改账户、预算、状态或素材。
```

“完整投放日”指账户时区刚结束的自然日；完整日期不代表转化回补或收入已全部到齐。账户确实尚未投放时，可改选 A，不把空响应直接解释为零花费。

</details>

<details>
<summary><strong>C · 已有 SOP：复制这条方法核对任务</strong></summary>

```text
请读取我提供的现有 SOP，并沿用已核对的账户与业务资料。
按原文来源整理适用范围、必须保持的规则、允许变化的部分、指标和观察条件。
列出缺失信息、条款冲突，以及当前工具不能完成或尚未验证的部分。
保留我的原方法，不自动改成默认模板；只有影响当前任务的缺项才追问。
先交付一份方法核对单和下一项任务建议，供我确认；暂不修改账户。
```

**完成标志：**每条关键规则都能追溯原文；已支持、待确认和缺能力分开。宿主工作流可以处理日报等任务，不要求所有 SOP 都转成 Python 的两类素材测试模板。

</details>

## 5. 对照一份结果，再检查自己的交付

下面是 B 路线的**虚构报告示例**，沿用[课程业务例子](build-from-zero.zh-CN.md)的数字，并补充虚构报告口径。不是实际读取回执，也不是本仓库程序的逐字生成输出。

> **范围：**课程账户 A；2026-09-23；America/Los_Angeles；美元。本例另设两个独立广告组，分别使用素材 A、B；下列数据按广告组统计，覆盖本例全部 2 个广告组。
>
> **来源：**虚构平台报表；提取时间设为 2026-09-24 09:00（同一时区），数据截至该时点；事件为预约表单提交，示例归因口径为点击后 7 天。真实任务须按实际来源填写。
>
> **概览：**花费 30 美元，4 次提交，平均每次提交 7.50 美元。A：18 美元 / 3 次 / 6 美元；B：12 美元 / 1 次 / 12 美元。
>
> **观察：**当天 A 的提交成本较低；样本较少，后续归因仍可能回补。
>
> **缺口：**销售确认的有效预约数未提供，无法比较真实获客质量；不把表单数当成有效客户数。
>
> **下一步：**由业务负责人补有效预约数据，Agent 在约定观察期后汇总复盘；目前没有足够依据宣布胜出或扩量。
>
> **本次动作：**仅分析，未修改账户。

| 交付检查 | 你应当看到什么 |
| --- | --- |
| A：投放准备 | 已知业务、资料来源、关键缺项、准备清单与候选方向；未确定预算保持待确认 |
| B：账户报告 | 账户、日期、时区、币种、层级、事件与归因口径、提取时间、覆盖和缺口 |
| C：方法核对 | 原文条款与处理结果对应；固定项、变量、冲突、支持情况和下一步 |
| 三条路线共同要求 | 事实与判断分开；谁补什么、何时继续清楚；准备或建议不写成已执行 |

B 路线抽取一个广告组，在后台用**相同日期、时区、层级、事件与归因口径**核对数字。私有记录中填：`对象｜报告值｜后台值｜两次读取时间｜是否一致／差异待查`。差异未解决就保留待核对，不直接写通过；账户总计与明细不要重复相加。

**部分结果也应清楚交接。** 例如：“目标账户基本信息已读到，报告接口拒绝访问；尚未取得表现数据。请账户管理员核对报表读取权限，解决后从第 3 步继续。本次未生成效果结论。”这是一份缺口交接，不是完成了账户报告。

<a id="next-task"></a>

## 6. 选择下一项任务

- **准备清单已确认：**按[日常工作流](workflow.zh-CN.md)准备一份素材测试或建单审阅单；未补齐的条件保持可见。
- **报告已核对：**先处理数据缺口，或提出需要你决定的调整方案。后续写入前再验证所需写入、读回能力和本批授权。
- **方法已确认：**直接交给 Agent 一项采用该方法的任务，例如日报或素材筛选；不会因为换任务就重做整个访谈。

任务记录默认由 Agent 根据对话与实际证据整理，你核对关键决定。需要保存时选择自己的私有目录，参考[任务记录模板](../templates/task-record.zh-CN.md)。跨会话复用需要可访问的已保存资料，不能仅凭一次对话假定永久记住。

<a id="troubleshooting"></a>

## 卡住时：查明缺口，然后继续原步骤

| 现象 | Agent 先检查并说明 | 你需要处理什么 | 从哪继续 |
| --- | --- | --- | --- |
| 读不到 `AGENTS.md` | 当前文件范围、缺失路径 | 打开解压后包含该文件的目录；见[加载排查](use-in-agent.zh-CN.md) | 第 1 步 |
| 显示已连接，没有读取工具 | 实际工具清单、客户端连接支持情况 | 对照官方指引核对服务地址和授权状态 | 第 2 步 |
| 有账户列表，没有目标账户 | 列表来源、已返回范围，不猜账户 ID | 核对平台身份和所选授权账户 | 第 3 步 |
| 报告为空或被拒绝 | 日期、时区、筛选、分页和实际错误类别 | 只补缺少的读取权限或范围，不先申请全部写权限 | 第 3 步，再重试 B |
| 有花费，缺转化或后端质量 | 缺事件定义、字段还是数据源 | 补事件口径或后端来源；可先接收部分报告 | 第 4 步原任务 |
| 开始要求建单或改预算 | 本次请求与拟调用工具是否匹配 | 保持本次只读任务，后续写入另审具体方案 | 第 4 步原任务 |

可直接发：“请列出这一步已确认的事实、实际错误类别、尚缺条件、由谁处理和恢复步骤。不要用示例数据代替读取结果，也不要自行安装或扩大权限。”
