# 第一次使用：Agent 工具 + Pipeboard，完成一次 Meta 只读检查

[English](first-check.md) · [项目首页](../README.zh-CN.md) · [加载排查](use-in-agent.zh-CN.md)

**本页只带你完成一件事：选定一个 Meta 广告账户，读取最近一个完整投放日，拿到一份有来源、可核对的检查报告。** 先完成第 1 步；已有可用连接时，可跳过第 2 步。全程不创建广告、不改预算、不启停对象。

## 这条路线验证到了哪里

| 项目 | 当前记录 |
| --- | --- |
| 固定路线 | 能读取项目文件并连接远程 MCP 的 Agent 工具 → Pipeboard Ads MCP → 一个选定的 Meta 账户 |
| 官方接入资料核对 | 2026-09-25；核对服务地址、连接方式和读取权限说明，来源见第 2 步 |
| 实际业务来源 | 作者曾通过 Agent 工具完成 Meta/TikTok 工作；任务和保留证据见[案例](case-studies.zh-CN.md) |
| 本教程完整实测 | 尚无按本页步骤从新环境开始的完整验收记录；历史使用不能代替这次验收 |
| 具体宿主及版本、独立试用者 | 待首轮试用填写；当前未宣称某个客户端版本或其他用户已通过 |

这里的“Agent 工具”沿用项目的通用称呼。具体客户端的 MCP 菜单、认证能力和项目规则入口需按该客户端确认；不支持远程 MCP 或无法读取仓库文件时，先解决对应缺口。[其他连接路线](platform-connectivity.zh-CN.md)仍可使用。

## 1. 准备项目与本次账户

- 获取[完整仓库](https://github.com/creator2000212-crypto/ad-ops-agent)，在 Agent 工具中打开包含 `AGENTS.md` 和 `docs/` 的根目录。仅粘贴 GitHub 地址不能保证规则已加载。
- 准备有权访问的 Meta 账户，先选一个；保留其原生账户 ID 用于私有会话中的身份核对。
- 有产品资料、目标事件和现有 SOP 就沿用；没有也能先检查数据覆盖、配置和明显缺项，不必先编一套投放方法。

## 2. 连接 Pipeboard

已有连接先核对下面的读取能力，无需重复购买或配置。尚未接入时，可[前往 Pipeboard 官网连接广告账户](https://pipeboard.co/#via=tian)。

1. 在 Pipeboard 的 Connections 页面连接 Meta，并选择本次需要的账户。
2. 在 Agent 工具的 MCP 配置中添加 **Streamable HTTP** 服务：`https://ads.mcp.pipeboard.co/`。支持相应 OAuth 流程的客户端按授权页面完成连接；其他客户端按官方指引把认证信息放入其安全配置。[统一 Ads MCP 指南](https://pipeboard.co/guides/ads-mcp)
3. 若已有 Meta 专用连接 `https://meta-ads.mcp.pipeboard.co/`，可继续使用，不必为本教程重配统一入口。[Meta MCP 指南](https://pipeboard.co/guides/meta-ads-mcp)
4. 为这次检查优先使用可用的只读凭据或工具限制。Pipeboard 的权限模式和账户限制受当前服务方案影响，请核对后台与[权限说明](https://pipeboard.co/guides/api-token-permissions)。聊天中写“只读”不等于服务端权限已经受限；凭据不要贴到对话、报告或仓库。

**这一步的完成标志：**宿主能发现真实的账户、对象及报告读取能力。工具名称与参数以本次可见的定义为准；“连接成功”提示本身不证明目标账户可读。

## 3. 加载规则，并核对账户

在已打开仓库的任务里发送：

```text
请读取当前项目根目录的 AGENTS.md，并按 docs/workflow.zh-CN.md 开展本次只读任务。
先确认能访问项目文件，说明采用的规则文件及无法确认的加载项。
检查已连接的 Pipeboard 工具，只使用账户、对象和报告读取能力。
列出当前获授权的 Meta 账户供我选择，不读取其他账户的表现数据。
如果我已指定账户，按原生 ID 核对；返回该账户名称、时区、币种与读取时间。
不要安装服务、扩大账户授权、创建对象或修改账户。
```

选择账户后应看到真实读取结果及来源；若只看到示例 JSON、`ready_simulation` 或模型声称“已接通”，这一步还没有完成。宿主自报规则文件可辅助检查；支持会话日志的客户端还可核对实际加载记录。[加载与排查](use-in-agent.zh-CN.md)

## 4. 发出第一项任务

确认所选账户后发送下面的任务，可补充现有产品资料和方法；无需手改配置文件。这里的“最近一个完整投放日”指按账户时区刚结束的自然日，不自动改选最近有消耗的日期；完整日也不代表归因回补或后端质量、收入已成熟。

```text
对刚才选定的一个 Meta 账户，检查按该账户时区刚结束的自然日，不跳过无消耗日。
先写明具体日期、时区、币种、统计层级、归因口径和数据截至时间。
读取当日账户及广告组表现，核对分页和覆盖范围；缺失数据不要补零。
复用已知产品、目标事件、已确认方法和上轮待办，只问会影响本次判断的缺项。
未确认目标成本或方法时，先报告事实和数据问题，不自行设停投或加预算阈值。
把平台归因事件与后端有效线索、收入或回收分开；缺少后端来源就明确写缺失。
注明归因回补及后端结果成熟度的已知限制，不把昨天的结果当成最终结果。
必要时读取相关对象当前状态，并把读取时点与当日效果统计分开。
交付：范围与完整性、主要观察、建议及依据、待确认项、来源和下一步。
本次只分析，不创建或修改任何广告、预算、状态或素材。
```

## 5. 核对第一份结果

| 报告部分 | 应当拿到什么 |
| --- | --- |
| 范围与完整性 | 一个明确账户、日期、时区、币种、数据截至时间；说明完整、部分可用或阻塞 |
| 数据与来源 | 报告层级、工具读取时间、分页/覆盖说明；已定义的结果事件及归因口径 |
| 观察 | 哪些对象值得关注、对应数据和限制；未知、无记录与真实零值分开 |
| 建议 | 依据用户方法或明确说明尚缺方法；建议与已执行动作分开 |
| 待办 | 具体缺什么、影响什么判断、由谁补充；本次未进行写入 |

抽取一个广告组，在 Meta 后台以**相同日期、时区、层级、事件与归因口径**复核关键数字。若不同，先对齐读取时间、过滤与口径并保留差异。不要把账户总数和明细简单相加，也不要据一天数据宣称方法已被证明有效。

**完成：**目标账户真实可读，所需数据覆盖已说明，报告及抽样核对有证据，使用者知道剩余限制。部分账户数据、缺少事件或仍有差异时可交付部分结果，同时标记未完成项；读取不到数据时只交接缺口，不生成假报表。

## 卡住时先看这里

| 现象 | 下一步 |
| --- | --- |
| 能聊天，但读不到 `AGENTS.md` | 确认打开的是完整仓库及本任务的文件访问范围 |
| MCP 显示已连接，但没有读取工具 | 检查客户端远程 MCP 支持、工具发现和连接状态；按实际工具定义诊断 |
| 能列账户，但目标账户不在其中 | 核对原平台身份、Pipeboard 选中的账户和当前权限，保留缺口 |
| 账户可读但报告为空 | 核对日期、时区、过滤、分页和权限；空响应不自动等于零花费 |
| 有花费，缺转化或后端质量 | 先说明缺少事件定义还是数据源；不据缺失值直接下优化结论 |
| 出现创建、上传或改预算请求 | 本任务不需要这些操作，停止该动作并回到读取范围 |

## 用一次独立试用检验教程

后续可邀请 2–3 位未参与项目搭建的人按本页试用，使用[任务模板的首次使用记录](../templates/task-record.zh-CN.md#first-use-validation)记录：宿主与版本、仓库版本、完成阶段、卡点、作者协助次数及最终交付。先在私有目录保存必要证据；对外分享前脱敏并取得参与者同意。模板本身不是试用结果。

完成第一次检查后，再按[首次配置](first-run.zh-CN.md)补充当前业务所需信息，或按[工作流](workflow.zh-CN.md)进入下一项任务。发布和配置任务需要另行准备具体方案与相应授权。
